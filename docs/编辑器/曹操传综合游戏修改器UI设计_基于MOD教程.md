# 曹操传综合游戏修改器 UI 设计（基于 MOD 认知的融合编辑器）

## 1. 设计前提

本设计参考了轩辕春秋教程：

- [用star175 5.6版exe做自己的曹操传MOD](https://xycq.org.cn/forum/viewthread.php?page=1&showoldetails=yes&tid=201504)

但吸收教程的方式，不是把界面照着“制作流程”来排，而是提炼出一个更重要的认知：

- 曹操传修改的真实对象不是文件
- 也不只是制作步骤
- 而是“武将”“关卡”“物品”“兵种”“头像”“存档”这些逻辑对象

教程能帮助我们理解这些对象之间天然会跨多个文件联动。例如：

- 一个武将对象同时涉及 `Data.e5`、`Face.e5`、`Pmapobj.e5`
- 一个物品对象同时涉及 `Data.e5`、`Imsg.e5`、商店、奖励事件、武将装备
- 一个关卡对象同时涉及 `R_*.eex`、`S_*.eex`、武将、奖励、地图、出战配置

所以这个工具应该是：

- `融合编辑器`

而不是：

- `流程式制作器`
- `多个单文件编辑器拼在一起的外壳`

---

## 2. 核心原则

### 2.1 按逻辑对象建页面

主页面必须围绕对象来建，而不是围绕文件。

正确例子：

- `武将编辑页面`
- `关卡编辑页面`
- `物品与装备页面`
- `兵种与策略页面`
- `头像与形象页面`
- `存档页面`

错误例子：

- `Data.e5 编辑页`
- `Face.e5 编辑页`
- `EEX 编辑页`
- `e5s 编辑页`

### 2.2 一个对象页面天然跨文件

如果“武将页面”里只能改能力，头像还得跳去 `Face.e5` 页面，R 形象还得跳去 `Pmapobj.e5` 页面，那它仍然不是融合编辑器。

融合编辑器的定义应该是：

- 用户打开“夏侯惇”
- 页面里就能看到并修改他的基础属性、兵种、装备、头像、R 形象
- 底层分别写回不同文件，但 UI 上是同一个对象

### 2.3 页面必须显式展示联动关系

真正难的不是“改值”，而是“改了以后会影响哪里”。

所以每个对象页面右侧都必须固定显示：

- `文件来源`
- `引用关系`
- `受影响对象`
- `保存前校验`

---

## 3. 总体 UI 架构

主界面建议采用：

- `对象导航`
- `对象工作区`
- `联动信息栏`

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 菜单栏 / 工具栏                                                      │
├───────────────┬──────────────────────────────────────┬───────────────┤
│ 左：对象导航   │ 中：对象工作区                        │ 右：联动信息栏  │
│               │                                      │               │
│ 项目总览       │ 当前对象主页面                        │ 对象属性        │
│ 武将           │ Tab: 基础 / 预览 / 关联 / 原始       │ 文件来源        │
│ 关卡           │                                      │ 引用关系        │
│ 物品与装备     │                                      │ 影响范围        │
│ 兵种与策略     │                                      │ 校验问题        │
│ 头像与形象     │                                      │ 快速跳转        │
│ 存档           │                                      │               │
│ 全局规则       │                                      │               │
│ 批处理工具     │                                      │               │
├───────────────┴──────────────────────────────────────┴───────────────┤
│ 状态栏：当前对象 / 当前工程 / 未保存改动 / 资源校验 / 引用计数        │
└──────────────────────────────────────────────────────────────────────┘
```

这里最关键的一点是：

- 左侧虽然有“头像与形象”
- 但它不是 `Face.e5` 查看器
- 它是一个视觉对象工作台

同理：

- 左侧有“全局规则”
- 也不是 `exe` 或配置文件编辑器
- 而是整个工程的规则对象页

---

## 4. 左侧对象导航设计

一级导航建议如下：

- `项目总览`
- `武将`
- `关卡`
- `物品与装备`
- `兵种与策略`
- `头像与形象`
- `存档`
- `全局规则`
- `批处理工具`

### 4.1 项目总览

作用不是编辑文件，而是展示当前工程健康状态：

- 已识别文件
- 引擎版本
- 头像槽规则
- `Ls12` 资源状态
- 存档样式识别
- 未解析资源提示
- 越界引用与缺失引用

### 4.2 武将

这是最核心的一类对象。

进入后左侧第二层应是：

- `武将列表`
- `势力分组`
- `兵种分组`
- `可用头像分组`

### 4.3 关卡

左侧第二层：

- `战役列表`
- `剧情段列表`
- `事件索引`
- `奖励与出战配置`

### 4.4 物品与装备

左侧第二层：

- `武器`
- `防具`
- `辅助`
- `消耗品`
- `宝物`
- `商店`

### 4.5 兵种与策略

左侧第二层：

- `兵种树`
- `转职链`
- `策略列表`
- `地形适应`

### 4.6 头像与形象

左侧第二层：

- `头像槽位`
- `武将视觉映射`
- `R 形象`
- `调色板实验`

视觉资源在产品层应进一步分组，避免“所有图片都进头像页”：

- `武将视觉`
  - `Face.e5`：头像
  - `Pmapobj.e5`：R 形象
  - `Unit_spc.e5` / `Unit_mov.e5` / `Unit_atk.e5`：S 形象动作
- `关卡场景`
  - `HM??.e5`：战场地图
  - `Smlmap.e5`：战场小地图
  - `Mmap.e5`：R 场景背景
  - `Gate.e5`：城门资源
- `界面与标题`
  - `Logo.e5`：开局、战前、结束、战败、单挑背景
  - `U_select.e5`：出战选人、练武场、对话背景
- `策略与特效`
  - `Meff.e5`：小策略图
  - `Mcall??.e5`：大策略图

因此：

- `头像与形象` 页面只聚焦武将视觉
- `关卡` 页面负责地图和场景资源
- `兵种与策略` 或独立特效页负责策略动画资源
- `全局规则` 或独立界面资源页负责标题和界面背景

### 4.7 存档

左侧第二层：

- `存档槽位`
- `武将状态`
- `物品库存`
- `战场状态`

### 4.8 全局规则

左侧第二层：

- `等级与经验`
- `转职规则`
- `标题与文本`
- `版本兼容规则`

## 5. 融合编辑器的核心页面

## 5.1 武将编辑页面

这是最能体现“融合”的页面。

### 这个页面必须同时联动

- `Data.e5`
- `Face.e5`
- `Pmapobj.e5`

### 页面布局

```text
┌───────────────────────────────────────────────────────────────────┐
│ 左：武将列表                                                      │
├───────────────┬──────────────────────────────────┬────────────────┤
│ 搜索/筛选      │ 中：当前武将编辑区               │ 右：联动栏      │
│                │                                  │                │
│ 武将名列表      │ Tab 基础信息                     │ 文件来源        │
│ 势力筛选        │ Tab 能力成长                     │ 使用资源        │
│ 兵种筛选        │ Tab 装备与兵种                   │ 影响分析        │
│ 有头像/无头像    │ Tab 头像与形象                   │ 保存校验        │
│ 有R形象/无R形象  │ Tab 原始数据                     │ 快速跳转        │
└───────────────┴──────────────────────────────────┴────────────────┘
```

### `基础信息` Tab

- 武将 ID
- 姓名
- 阵营/敌我
- 初始等级
- 经验
- 兵种

### `能力成长` Tab

- 五维基础值
- 成长倾向
- 等级预估曲线
- 与同兵种平均值对比

### `装备与兵种` Tab

- 武器
- 防具
- 辅助
- 可转职路线
- 可学策略

### `头像与形象` Tab

这块必须直接集成：

- 当前 `face_id`
- 头像缩略图
- 切换头像槽位
- 曹操 `000-007` 表情组特殊说明
- 当前 `R` 形象预览
- 从资源库挑选头像
- 导入 / 替换头像

这一步就是你强调的关键：

- 在武将页面里直接改 `Data.e5 + Face.e5 + Pmapobj.e5`
- 而不是让用户跳去另一个文件页

### `原始数据` Tab

- `Data.e5` 记录偏移
- `Face.e5` 块号
- `Pmapobj.e5` 块号

### 武将页右侧联动栏

- 当前编辑涉及哪些底层文件块
- 头像改动会影响该武将在全局资源中的视觉表现
- 兵种改动会影响哪些策略和地形表现
- 切换头像或 R 形象时可跳转到资源页
- 删除或替换时的风险提示

## 5.2 关卡编辑页面

关卡页面也必须是对象页，而不是脚本页。

### 同时联动

- `R_*.eex`
- `S_*.eex`
- 武将对象
- 物品对象
- 地图资源
- 出战配置

### 页面主区

- 关卡流程图
- 事件列表
- 参战武将
- 奖励物品
- 胜败条件
- 战前 / 战中 / 战后分段

### 这个页面里应该能直接做的事

- 在事件里选择武将，而不是手填 ID
- 给奖励事件直接绑定物品对象
- 点击头像发言可跳转到对应武将和头像
- 检查某个事件引用的对象是否缺失

---

## 5.3 物品与装备页面

### 同时联动

- `Data.e5`
- `Imsg.e5`
- 商店数据
- 武将装备引用
- 剧本奖励引用

### 页面结构

- 左：物品分类树
- 中：属性 + 图标 + 说明 + 装备对象
- 右：商店引用、奖励引用、装备武将、平衡提示

### 这页体现“融合”的点

- 改物品名时，同时更新说明和搜索索引
- 改物品图标时，直接预览装备后的视觉效果
- 改可装备兵种时，立即列出受影响武将

---

## 5.4 兵种与策略页面

### 同时联动

- `Data.e5` 兵种
- `Data.e5` 策略
- 地形
- 武将引用
- 转职链

### 页面结构

- 左：兵种树 / 策略列表
- 中：成长、地形、策略、转职编辑
- 右：引用武将、强度警告、兼容校验

### 融合点

- 改兵种时，武将页的兵种选择立即同步
- 改策略可学范围时，相关武将和职业自动重算提示

---

## 5.5 头像与形象页面

这页不是 `Face.e5` 浏览器，而是视觉对象页面。

### 同时联动

- `Face.e5`
- `Pmpalet.e5`
- `Spalet.e5`
- `Pmapobj.e5`
- 武将对象

这页明确不负责：

- `Mmap.e5`
- `HM??.e5`
- `Gate.e5`
- `Logo.e5`
- `U_select.e5`
- `Meff.e5`
- `Mcall??.e5`
- `Unit_spc.e5` / `Unit_mov.e5` / `Unit_atk.e5`

### 页面结构

- 左：头像槽位 / 武将映射切换
- 中：大图预览 / 调色板预览 / 替换工具
- 右：使用该头像的武将、脚本引用、导出参数

### 页面必须内建的认知

- `000-007` 为曹操表情组
- `008+` 为后续武将顺排
- 当前最可信的导出规则是 `Pmpalet[0] + channel-order 120`
- `Pmapobj.e5` 属于武将 R 形象对象

### 这页应支持

- 按武将找头像
- 按头像找武将
- 按武将同时查看头像和 R 形象
- 替换后回看影响对象
- 对比不同调色板渲染效果

### 同时联动

- `Sv??d.e5s`
- `Sv??s.e5s`
- `Sv??e.e5s`
- 武将对象

### 页面结构

## 5.7 全局规则页面

这页也依然是逻辑对象页，不是底层配置页。

### 同时联动

- `Data.e5`
- `Imsg.e5`
- 引擎规则
- 全局文本

### 页面内容

- 最大等级
- 转职等级
- 升级经验曲线
- 标题与系统文本
- 兼容规则说明

### 融合点

- 改最大等级时，提示受影响兵种和人物成长
- 改标题时，同时预览界面文本效果

## 6. 页面共通交互规则

所有对象页尽量保持同一交互模型：

- 左侧选对象
- 中央改对象
- 右侧看联动

中央标签建议统一成：

- `基础`
- `预览`
- `关联`
- `原始`

这样用户在不同对象页之间切换时不会迷路。

---

## 7. 这才算“融合编辑器”的判定标准

如果一个页面满足下面这些条件，才算真的融合：

1. 用户面对的是逻辑对象，不是文件块。
2. 一次编辑可以覆盖该对象涉及的多个底层文件。
3. 页面里能看到这个对象和其他对象的引用关系。
4. 保存前能提示跨文件影响和风险。
5. 可以从任意对象快速跳到关联对象，而不是自己记 ID。

所以：

- `武将页里能改头像`，这叫融合
- `物品页里能看到谁在用它`，这叫融合
- `关卡页里能直接选武将和奖励物品`，这叫融合

反过来：

- `Data.e5 页 + Face.e5 页 + EEX 页` 并排放着
- 这不叫融合，只是聚合

---

## 8. 推荐的首版 UI 落地顺序

如果开始做原型，建议按“最能体现融合价值”的顺序落地：

1. `武将编辑页面`
2. `头像与形象页面`
3. `物品与装备页面`
4. `关卡编辑页面`
5. `存档页面`

原因很简单：

- 武将页最容易验证“跨 `Data.e5 + Face.e5 + Pmapobj.e5`”
- 头像页最容易把我们已经研究出的资源规则真正用起来
- 这两页做好之后，整个产品的“融合编辑器”气质就会立住

---

## 9. 当前版本的一句话定义

这个修改器应该被设计成：

- `面向逻辑对象的曹操传融合编辑器`

而不是：

- `按文件拆开的研究工具`
- `按制作步骤排布的向导式工具`
