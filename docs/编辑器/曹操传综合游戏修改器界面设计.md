# 曹操传综合游戏修改器界面设计

## 1. 核心方向

这个综合修改器不应该按“文件”来组织页面。

如果界面是：

- `Data.e5 编辑页`
- `Face.e5 编辑页`
- `EEX 编辑页`
- `存档编辑页`

那本质上仍然只是“把多个单文件编辑器放进一个壳子里”。

更合理的方向应该是：

- 用户面对的是“武将”“关卡”“物品”“头像体系”“存档槽”“版本规则”
- 底层文件只是数据来源和保存目标
- 一个页面天然串起多个文件

也就是说，修改器的主入口应是“对象工作台”，而不是“文件工作台”。

---

## 2. 底层文件与对象的关系

虽然界面不按文件组织，但底层仍然要联动这些文件：

- `Data.e5`：武将、兵种、物品、商店、地形、策略
- `Imsg.e5`：说明文本
- `Face.e5`：头像
- `Pmapobj.e5`：R 形象
- `Pmpalet.e5` / `Spalet.e5` / `Logo_p.e5`：调色板
- `R_*.eex` / `S_*.eex`：关卡与剧情事件
- `Sv???.e5s`：存档槽状态

但这些文件应隐藏在对象层背后。

例如：

- “武将工作台”同时读 `Data.e5 + Face.e5 + Pmapobj.e5`
- “关卡工作台”同时读 `R/S 脚本 + 武将数据 + 地图资源 + 奖励物品`
- “头像与形象工作台”同时读 `Face.e5 + Pmapobj.e5 + 调色板 + 武将引用`

---

## 3. 主界面总布局

建议主窗口依然保持当前 PyQt 工具的桌面风格，但把信息架构改成真正的对象式布局。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 菜单栏 / 工具栏                                                      │
├───────────────┬──────────────────────────────────────┬───────────────┤
│ 左侧对象树     │ 中央工作台                           │ 右侧联动栏      │
│               │                                      │               │
│ 项目总览       │ Tab 1: 列表                         │ 当前对象属性    │
│ 武将工作台     │ Tab 2: 预览                         │ 影响范围        │
│ 关卡工作台     │ Tab 3: 关联对象                     │ 引用关系        │
│ 物品工作台     │ Tab 4: 原始数据/差异               │ 校验提示        │
│ 兵种策略台     │                                      │               │
│ 头像形象台     │                                      │               │
│ 存档工作台     │                                      │               │
│ 版本规则台     │                                      │               │
├───────────────┴──────────────────────────────────────┴───────────────┤
│ 状态栏：当前对象 / 当前目录 / 未保存改动 / 校验结果 / 引用计数        │
└──────────────────────────────────────────────────────────────────────┘
```

## 4. 左侧导航树

左侧不应再是“文件分类树”，而是“对象工作台树”。

建议一级节点：

- `项目总览`
- `武将工作台`
- `关卡工作台`
- `物品与装备工作台`
- `兵种与策略工作台`
- `头像与形象工作台`
- `存档工作台`
- `版本与规则工作台`
- `批处理工具`

### 4.1 项目总览

显示整个游戏目录的健康状态：

- 资源是否齐全
- 是否存在越界引用
- 是否有未识别的存档样式
- 当前版本规则是什么

### 4.2 武将工作台

面向“武将对象”。

### 4.3 关卡工作台

面向“某一战 / 某一剧情段”。

### 4.4 物品与装备工作台

面向“物品对象”。

### 4.5 兵种与策略工作台

面向“兵种成长 / 策略习得体系”。

### 4.6 头像与形象工作台

面向“人物视觉资源对象”，而不是单纯 `Face.e5` 浏览器。

### 4.7 存档工作台

面向“存档槽对象”，而不是 `Sv???.e5s` 文件。

### 4.8 版本与规则工作台

显式管理各种隐性规则，例如：

- `Data.e5` 解压偏移映射
- `Face.e5` 编号规则
- 存档中文 45 字节头 / 日文 30 字节头布局
- 调色板解释规则

---

## 5. 中央工作台通用结构

每个对象工作台，中央区域都尽量保持同一交互模式：

- `列表`
- `预览`
- `关联`
- `原始`

### 5.1 列表

对象表格或树，支持：

- 搜索
- 过滤
- 排序
- 批量编辑

### 5.2 预览

对象的游戏内表现：

- 头像
- 图标
- 兵种能力
- 关卡流程
- 资源状态

### 5.3 关联

这个对象被哪些别的对象使用。

### 5.4 原始

高级用户查看：

- 原始偏移
- 源文件
- 原始块编号
- 十六进制视图

---

## 6. 右侧联动栏

右侧栏不是纯属性面板，而是“联动面板”。

固定包含：

- `当前对象属性`
- `文件来源`
- `引用关系`
- `受影响对象`
- `保存前校验`

例如选中一个头像槽位时：

- 当前对象属性：`face_id`、尺寸、调色板、槽位名
- 文件来源：`Face.e5` 第几块
- 引用关系：哪些武将、哪些剧本头像事件引用它
- 受影响对象：如果替换它，会影响谁
- 保存前校验：调色板是否匹配、是否越界

---

## 7. 真正跨文件的核心工作台

下面这些页面设计，重点就是避免“单文件编辑器思维”。

## 7.1 武将工作台

这是综合修改器最重要的一页。

### 它联动哪些文件

- `Data.e5`：属性、等级、兵种、装备
- `Face.e5`：头像
- `Pmapobj.e5`：R 形象

### 中央标签

- `武将列表`
- `能力与成长`
- `视觉资源`
- `原始数据`

### 列表列建议

- `ID`
- `姓名`
- `头像槽`
- `R形象`
- `兵种`
- `等级`
- `武器`
- `防具`
- `辅助`
- `出场次数`

### 预览内容

- 小头像
- R 形象缩略图
- 五维条
- 兵种说明
- 可学习策略

### 真正的联动价值

用户改一个武将时，右侧应该立即告诉他：

- 当前编辑涉及 `Data.e5`、`Face.e5`、`Pmapobj.e5` 的哪些资源
- 头像或兵种改动会影响哪些地方
- 切换头像或 R 形象时可以跳转到对应资源对象

这才是“综合修改器”，而不是“Data.e5 行编辑器”。

## 7.2 关卡工作台

这页也必须跨文件。

### 它联动哪些文件

- `R_*.eex`
- `S_*.eex`
- 武将数据
- 物品奖励
- 地图资源
- 头像与形象资源

### 中央标签

- `关卡总览`
- `事件流`
- `参战配置`
- `奖励与条件`
- `资源引用`

### 重点

用户应当是打开“颍川之战”这种关卡对象，而不是自己先判断它对应哪几个 `R/S` 文件。

点到一个事件时，界面应该直接显示：

- 事件涉及的武将名
- 头像预览
- 奖励物品图标
- 跳转到关联对象

## 7.3 物品与装备工作台

### 联动文件

- `Data.e5` 物品定义
- `Item.e5` / `Itemicon.dll` 图标
- 商店数据
- 武将装备
- 剧本奖励事件
- 存档持有状态

### 中央标签

- `物品列表`
- `图标预览`
- `装备关系`
- `商店分布`
- `事件引用`

重点不是“改 item 一行数据”，而是回答：

- 谁在用这件装备
- 哪些商店卖它
- 哪些关卡送它

## 7.4 兵种与策略工作台

### 联动文件

- `Data.e5` 兵种
- `Data.e5` 策略
- 地形适应
- 武将兵种引用
- 剧本中的兵种配置

### 中央标签

- `兵种表`
- `策略表`
- `地形适应`
- `武将引用`
- `剧本引用`

这里用户修改的是“体系”，不是某一个文件块。

## 7.5 头像与形象工作台

这页尤其不能设计成“Face.e5 查看器”。

### 联动文件

- `Face.e5`
- `Pmapobj.e5`
- `Pmpalet.e5`
- `Spalet.e5`
- 武将数据
- 剧本头像调用

### 中央标签

- `头像槽位`
- `曹操表情组`
- `武将映射`
- `R形象映射`
- `调色板实验`
- `引用关系`

### 这里应该显式写出已知规则

- `000-007`：曹操的不同表情
- `008+`：后续一个武将一个头像顺序

这页的核心问题是：

- 某个 `face_id` 属于谁
- 它是不是表情槽
- 替换后会影响哪些武将和事件

## 7.6 存档工作台

### 联动文件

- `Sv??d/e/s.e5s`
- 武将数据
- 装备与物品
- 关卡进度

### 中央标签

- `存档槽列表`
- `队伍状态`
- `装备与仓库`
- `剧情进度`
- `与主数据差异`

这页的核心价值不是“存档十六进制编辑”，而是：

- 比较“主数据定义”和“存档实际状态”
- 快速跳转到相关武将或物品对象

## 7.7 版本与规则工作台

这是综合修改器区别于传统工具的重要页面。

### 应显式展示的规则

- `Data.e5` 解压后偏移 = 配置偏移 - `0x18C`
- `Face.e5` 槽位规则
- `Pmpalet[0] / Spalet[0]` 头像调色板
- `BRG -> RGB` 通道顺序
- 存档中文、日文头布局与 `0x0F` 偏移差

这页让工具本身知道“怎么解释数据”，而不是把这些经验散落在代码和论坛帖子里。

## 8.1 菜单栏

- `文件`
  - 打开游戏目录
  - 保存当前对象
  - 保存全部
  - 导出补丁
  - 导出 JSON
- `编辑`
  - 撤销
  - 重做
  - 批量替换
- `查看`
  - 对象树
  - 原始数据
  - 引用关系
- `工具`
  - 引用检查
  - 一致性检查
  - 导出头像 PNG
  - 调色板实验
- `剧本`
  - 打开关卡工作台
  - 全局事件搜索
- `帮助`
  - 格式说明
  - 关于

## 8.2 工具栏

保留高频功能：

- 打开目录
- 保存全部
- 撤销 / 重做
- 全局搜索
- 引用检查
- 导出资源

## 9. 首版最值得先做的两个页面

如果要做出“真的是综合修改器”的感觉，首版最值得先实现的是：

1. `武将工作台`
2. `头像与形象工作台`

原因：

- 武将工作台天然串起最多文件
- 头像与形象工作台最容易做出“跨文件联动”的视觉效果

而不是先做：

- `Data.e5 编辑页`
- `Face.e5 编辑页`

因为那样又会退回单文件编辑器思路。

---

## 10. 下一步建议

建议下一步直接实现：

1. 主窗口外壳
2. 左侧对象树
3. 武将工作台 UI
4. 头像与形象工作台 UI

也就是先把“对象工作台”路线落实到界面骨架，再接数据。
