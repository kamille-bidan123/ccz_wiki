# 本地旧引擎 EEX 二进制格式说明

## 概述

EEX 文件是《三国志曹操传》事件脚本文件，采用二进制格式存储游戏事件和剧情脚本。本文档描述当前目录 `ccz/Ekd5.exe` 所使用的**旧引擎**格式；Star/新引擎扩展指令不属于本文规格。

本地旧引擎在 `0x00410A0F` 将 opcode 与 `0x6B` 比较，超过
`0x6B` 即返回错误码 5。因此本文命令域严格限定为 `0x00..0x6B`。
详细验证与版本隔离结论见 `EEX_COMMAND_SPECS草案.md`。

## 基本数据类型

| 类型 | 大小 | 说明 |
|------|------|------|
| u8 | 1 字节 | 无符号 8 位整数 |
| u16 | 2 字节 | 无符号 16 位整数（小端序） |
| u32 | 4 字节 | 无符号 32 位整数（小端序） |
| bool | 2 字节 | 布尔值：`\x01\x00` = true，`\x00\x00` = false |
| string | 变长 | 以 `\x00` 结尾的字符串（GB18030 编码） |

## 文件结构

```
┌─────────────────────────────────────┐
│           文件头 (10 字节)            │
├─────────────────────────────────────┤
│        场景偏移表 (变长)              │
├─────────────────────────────────────┤
│              Scene 0                │
├─────────────────────────────────────┤
│              Scene 1                │
├─────────────────────────────────────┤
│               ...                   │
└─────────────────────────────────────┘
```

### 1. 文件头 (Magic)

**偏移**: 0x00
**大小**: 10 字节
**内容**: `45 45 58 00 01 02 00 00 00 00` (ASCII: "EEX\x00\x01\x02\x00\x00\x00\x00")

```
偏移    字节          说明
0x00    45 45 58 00   "EEX\0" 文件标识
0x04    01 02         固定格式标记（旧引擎语义未单独拆分）
0x06    00 00 00 00   固定零字节
```

对本地旧引擎而言，上述 10 字节整体按固定魔数
`45 45 58 00 01 02 00 00 00 00` 验证。没有本地调用证据证明
`01 02` 是可变“版本号”，因此不采用新引擎资料中的版本字段解释。

### 2. 场景偏移表

**偏移**: 0x0A
**格式**: u32 数组（小端序）

场景偏移表存储每个 Scene 在文件中的起始位置。第一个 u32 值是 Scene 0 的偏移，也是偏移表结束的位置。

```
偏移表结构:
┌──────────────┐
│ scene_offset[0] │  <- 第一个 Scene 的偏移，也是偏移表结束位置
├──────────────┤
│ scene_offset[1] │
├──────────────┤
│     ...      │
├──────────────┤
│ scene_offset[n] │
└──────────────┘
```

**读取逻辑**:
```python
scene_offset = []
scene_offset.append(u32(f.read(4)))  # 第一个偏移
while f.tell() != scene_offset[0]:    # 直到到达第一个 Scene
    scene_offset.append(u32(f.read(4)))
```

## Scene 结构

每个 Scene 包含多个 Section（章节）。

```
┌───────────────────────────┐
│  section_count (u16)      │  Section 数量
├───────────────────────────┤
│  Section 0                │
├───────────────────────────┤
│  Section 1                │
├───────────────────────────┤
│  ...                      │
└───────────────────────────┘
```

## Section 结构

每个 Section 分为两部分：**测试条件部分** 和 **事件部分**。

```
┌─────────────────────────────────────┐
│  section_len (u16)                  │  Section 长度
├─────────────────────────────────────┤
│  测试条件部分 (Test Conditions)      │
│  - 条件命令列表                      │
│  - 0x0000 (事件结束标记)             │
│  - event_len (u16)                  │  事件部分长度
├─────────────────────────────────────┤
│  事件部分 (Events)                   │
│  - 事件命令列表                      │
│  - 0x0000 (Section 结束标记)         │
└─────────────────────────────────────┘
```

### Section 解析状态

解析 Section 时有两个状态：
- `test`: 正在解析测试条件部分
- `event`: 正在解析事件部分

当遇到 `0x0000` 命令时：
- 如果状态是 `test`: 读取 u16 (event_len)，切换到 `event` 状态
- 如果状态是 `event`: Section 结束

## 常用参数读取方法

### 人物 ID (read_people)
```
02 00 [u16 people_id]
```

### 字符串消息 (read_msg)
```
05 00 [string] 00
```
字符串以 `\x00` 结尾，使用 GB18030 编码。常规汉字与 GBK 相同，
但不能用 GBK 代替完整解码器。

### 32位值 (read_value)
```
04 00 [u32 value]
```

### 方向 (read_dire)
```
2B 00 [u16 direction]
```

### 动作 (read_action)
```
0D 00 [u16 action_id]
```

### 布尔参数 (read_bool_arg)
```
26 00 [bool]  // 01 00 = true, 00 00 = false
```

### 人物等级 (read_people_lv)
```
3E 00 [u16 level]
```

### 装备等级 (read_equipt_lv / read_item_lv)
```
49 00 [u16 level]
```

### 运算符 (read_operator)
```
34 00 [u16 operator]
```

### 属性 (read_attr)
```
23 00 [u16 attr_id]
```

### 带类型标记的 u16 (read_type_u16)
```
[type_id as u16] [u16 value]
```
例如：`read_type_u16(0x47)` 会读取 `47 00 [u16 value]`

## 命令详细格式

### 0x00 - 事件结束
```
[u16: 0x0000]
```
在测试条件部分：后跟 `[u16 event_len]`
在事件部分：Section 结束

### 0x01 - 子事件开始
```
[u16: 0x0001]
[测试条件命令]
[u16 event_len]
[事件命令列表]
[u16: 0x0000]  // 子事件结束
```

### 0x02 - 内部消息
```
[u16: 0x0002]
05 00 [string msg] 00
```

### 0x04 - 询问测试
```
[u16: 0x0004]
26 00 [bool value]
```

### 0x05 - 变量测试
```
[u16: 0x0005]
35 00 [u16 true_count]
[u16 true_var_1] ... [u16 true_var_n]
35 00 [u16 false_count]
[u16 false_var_1] ... [u16 false_var_m]
```

### 0x08 - 菜单控制
```
[u16: 0x0008]
2E 00 [bool value]
```

### 0x09 - 延时
```
[u16: 0x0009]
04 00 [u32 ticks]  // 实际延时 = ticks * 10 秒
```

### 0x0B - 变量赋值
```
[u16: 0x000B]
04 00 [u32 var_idx]
27 00 [bool value]
```

### 0x0F - 结局设定
```
[u16: 0x000F]
12 00 [u16 end_type]  // 0=红线, 1=黄线, 2=蓝线
```

### 0x11 - 脚本跳转
```
[u16: 0x0011]
37 00 [u16 jump_target]
```

### 0x14 - 对话
```
[u16: 0x0014]
05 00 [string msg] 00
```

### 0x15 - 双人对话
```
[u16: 0x0015]
02 00 [u16 people_id1]
02 00 [u16 people_id2]
05 00 [string msg] 00
```

### 0x1F - 地图视野切换
```
[u16: 0x001F]
04 00 [u32 x]
04 00 [u32 y]
```

### 0x21 - 战斗物品添加
```
[u16: 0x0021]
04 00 [u32 x]
04 00 [u32 y]
10 00 [u16 item_type]
26 00 [bool focus_camera]
26 00 [bool skip_presentation]
```

本地旧引擎 `0x00413EFB` 与 `0x58` 障碍命令共用地图对象函数
`0x00456140/0x004567C1`。`focus_camera` 在添加和移除时定位镜头；
`skip_presentation` 只在添加路径生效，跳过镜头、音效和等待。原版
EEX 没有使用本命令，但调用参数已经由旧引擎本身确定。

### 0x23 - 播放音效
```
[u16: 0x0023]
1E 00 [u16 se_id]
04 00 [u32 count]
```

### 0x24 - 播放音乐
```
[u16: 0x0024]
09 00 [u16 track_id]
```

### 0x27 - 背景设定
```text
[u16: 0x0027]
2D 00 [u16 background_type]
0C 00 [u16 outside_map_id]
1A 00 [u16 chinese_map_id]
1C 00 [u16 inside_map_id]
15 00 [u16 battle_map_id]
```

### 0x28 - 设置保留脚本值

```text
[u16: 0x0028]
36 00 [u16 reserved_value]
```

本地 117 个原版脚本未使用该命令，但本地主程序解析函数
`0x00414361` 明确读取参数标记 `0x0036` 和一个 `u16le`，因此结构可以
确定。随后 `0x00418518` 仅把该值写入脚本对象 `+0x203C`；对应读取函数
`0x00418531` 在整份本地 `Ekd5.exe` 中没有调用点，也没有直接访问该
字段的其他路径。因此对当前旧引擎而言，它是一个**写入后不消费的保留
脚本值**，没有可观察的游戏效果。

Star 新引擎后来把同一 opcode 改成“自由 R 开关”，这是版本重定义，
不能倒推到本地旧引擎。

## JSON 数据结构

解析后的 JSON 结构：

```json
[
  [  // Scene 0
    [  // Section 0
      { "type": 0x02, "msg": "测试条件消息" },  // 测试条件部分
      { "type": 0x00, "_section_end": true },   // 分界标记
      { "type": 0x14, "msg": "对话内容" },      // 事件部分
      { "type": 0x30, "people_id": 1, ... }
    ],
    [  // Section 1
      ...
    ]
  ],
  [  // Scene 1
    ...
  ]
]
```

## 注意事项

1. **字节序**: 所有多字节数值使用小端序 (Little Endian)
2. **字符串编码**: 使用 GB18030；常规文本兼容 GBK，但原版语料中有
   22 条字符串包含 GB18030 四字节字符，按 GBK 写回会失败或损坏
3. **布尔值**: 占用 2 字节，`\x01\x00` = true，`\x00\x00` = false
4. **Section 分界**: 测试条件和事件部分以 `0x0000 + event_len` 分隔
5. **子事件**: 使用栈结构处理嵌套的子事件块

## 全量验证

- 59 个 `R_*.eex` 与 58 个 `S_*.eex`，共 117 个文件全部解析成功；
- `EEX -> AST -> EEX`：117/117 逐字节相同；
- `EEX -> AST -> DSL -> AST -> EEX`：117/117 逐字节相同；
- 原版语料没有 `>=0x6C` opcode；
- 写回器会拒绝超过本地旧引擎上限 `0x6B` 的命令。
