## 当前目录里的两种语言布局

此前把 21709 字节文件暂称为“变体样式”。继续检查后可以确定，这四份
不是损坏文件或未知 MOD 布局，而是**日文原版布局**：

- `Sv03d.e5s` 开头含 Shift-JIS 字符串 `シナリオ名`
- 同槽 `Sv03s.e5s` 的胜利条件也是可正常解码的 Shift-JIS 日文
- 21709 字节文件的人物表从 `0x14CD` 开始，仍是完整的
  `512 × 0x20` 字节，恰好结束于文件末尾
- 日文版与中文版的已知逻辑偏移统一相差 `0x0F`

差异来自文件头的显示文字区：中文版保留 45 字节，日文版保留 30
字节，后者少 `0x0F` 字节。人物、仓库和进度数据并没有换成另一套记录
格式。

## `Sv??s.e5s` 战场状态

文件固定大小为 5891 字节。已验证战场单位表：

```text
表偏移 0x515
115 个槽
每槽 26 字节
表后为 40×40、每格 1 字节的单位占位表
```

| 槽内偏移 | 类型 | 含义 |
| ---: | --- | --- |
| `+0x00` | `u16le` | 武将编号；空槽常为 `FFFF` |
| `+0x02` | `u16le` | 当前 HP |
| `+0x04` | `u16le` | 当前 MP |
| `+0x06` | `u8` | 出场顺序 |
| `+0x07` | `u8` | 阵营：我军 0、友军 1 等 |
| `+0x08` | `u8` | 横坐标 |
| `+0x09` | `u8` | 纵坐标 |
| `+0x0A` | `u8` | AI 移动目标横坐标 |
| `+0x0B` | `u8` | AI 移动目标纵坐标 |
| `+0x0C` | `u8` | AI 目标单位的出场顺序；`FF` 表示没有单位目标 |
| `+0x0D` | `u8` | AI 行动顺序/调度序号；`FF` 表示不参加自动行动调度 |
| `+0x0E` | `u8` | 上场状态：0 空槽、2 在地图、3 已配置但当前不占格 |
| `+0x0F` | `u8` 位域 | 行动、移动、形象镜像、地图绘制抑制和临时离场标志 |
| `+0x10` | `u8` | AI 类型；友敌军与 `Sv??e[+0x0A]` 对应 |
| `+0x11` | `u8` | 朝向：上、右、下、左 |
| `+0x12..0x17` | 6 字节 | 攻、防、精神、敏捷、士气、移动状态 |
| `+0x18` | `u8` | 中毒/麻痹/禁咒/混乱组合位 |
| `+0x19` | `u8` | 是否显示撤退；由 EEX `0x1B`“撤退显示设定”写入 |

这里的单位数由本地旧引擎保存函数直接限定为 `0x73 = 115`，与
`Sv??e` 的 15 个我军、20 个友军、80 个敌军槽一致。旧的
“176 个单位记录、表后 14 字节”解释只是把剩余长度继续按 26 除所得，
与实际循环边界不符。

单位记录后恰有 `0x640 = 1600` 字节。它是 40×40 的单位占位表：

- 空格为 `0xFF`；
- 非空值为 `0..114` 的单位槽号；
- 记录坐标 `(x, y)` 到线性下标的投影为
  `(y // 2) × 40 + x + (y % 2) × 20`。

例如 `Sv00s` 的 0 号单位记录坐标为 `(10, 6)`，占位表下标为
`3×40+10=130`，该字节正是 0；16 号单位坐标为 `(8, 5)`，下标为
`2×40+8+20=108`，该字节正是 16。仓库中十份战场存档的全部在场单位
均可用此公式互相校验。保存路径 `0x0044F5BE` 先循环调用
`0x00442BF6` 写 115 条 26 字节记录，再固定写入 `0x640` 字节占位表；
读取路径 `0x0044F6E6` 执行完全对称的操作。

字段定名同样以旧引擎调用为准：

- 运行时 `+0x09/+0x0A`（文件 `+0x0A/+0x0B`）组成坐标对象。
  `0x0044268C` 在 AI 指定移动目的地时写入这两个字节，并把运行时
  `+0x08`（文件 `+0x0C`）重置为 `FF`；
- `0x0041C310` 返回运行时 `+0x08`。单位撤退路径
  `0x00441744..0x00441975` 会遍历全部 115 个单位，将该值与撤退单位的
  `+0x04` 出场顺序比较；相等时清为 `FF` 并重新安排 AI 目标。因此
  文件 `+0x0C` 是目标单位的出场顺序，而不是保留字节；
- `0x0043FCC9` 仅在运行时 `+0x0C == 2`（文件 `+0x0E`）时把单位写入
  占位表；样本中空槽为 0，所有占格单位为 2，非空但不占格记录为 3；
- `0x00425AD0` 返回运行时 `+0x0E`（文件 `+0x10`），战斗 AI 分支会
  与 1、2、3、4、7 等类型值比较，且友敌军样本与 `Sv??e` 的
  `ai_type` 一致；
- 主 AI 调度循环 `0x0044E9BF..0x0044EA87` 递增当前行动序号，并通过
  `0x00425AB0` 读取运行时 `+0x0B`（文件 `+0x0D`）逐一比较，因此
  该字节是 AI 行动顺序/调度序号；样本中的 `FF` 表示不加入自动行动
  队列；
- `0x00425AF0` 对运行时 `+0x0D`（文件 `+0x0F`）执行掩码测试，
  `0x00442718` 先清后置入掩码，`0x00406690` 执行清位；调用点至少使用
  `02/04/08/20/80`，并会以 `06` 同时设置两位，说明它是复合运行标志，
  不是单一“已行动”布尔值。各位的旧引擎消费路径为：

| 掩码 | 解析名 | 本地旧引擎行为 |
| ---: | --- | --- |
| `0x02` | `has_acted` | 攻击、策略或其他最终行动完成后置位；回合复位时与 `0x04` 一起清除 |
| `0x04` | `has_moved` | 完成移动后先置位；最终行动完成时与 `0x02` 一起成为 `0x06` |
| `0x08` | `sprite_mirrored` | `0x0043FD34` 随左右方向切换，并用 `UNIT_MOV.E5` 重绘相反朝向 |
| `0x20` | `map_draw_suppressed` | 攻击/特效动画开始前置位、结束后清除，避免普通地图层重复绘制 |
| `0x80` | `temporarily_inactive` | 临时移出占位和目标选择；单位重新放回地图后清除 |

`0x01/0x10/0x40` 没有通过上述 helper 的调用点，当前十份原版存档也
没有出现。解析器保留完整 `runtime_flags`，另导出
`runtime_flags_decoded` 和 `unknown_bits`，不为无证据位强行命名。

轩辕春秋 2005 年旧引擎问答也从 `0x515` 起按 26 字节解释原版记录，
并把样例中的 `0x0E` 概括为“行动完毕”。本地机器码进一步证明
`0x0E = 0x02 + 0x04 + 0x08`：前两位分别是行动、移动，第三位是形象
镜像，不能继续把整个字节当作单一布尔值；
- EEX `0x1B` 的执行路径 `0x00413C56` 最终调用 `0x00418CB0`，把
  布尔值写入运行时 `+0x20`；保存后正是文件 `+0x19`。

全局已知偏移：

- `0x25`：已完成回合数
- `0x26`：回合上限
- `0x2D..0x2E`：天气相关字节

## `Sv??e.e5s` 扩展状态

文件固定大小为 10330 字节。此前把开头的 `115 × 15` 记录误判为
“115 个 R 场景状态”；与同一关的 `S_00.eex` 和 `Sv00s.e5s`
逐槽核对后，现已确定它是**战场出场配置表**：

| 范围 | 长度 | 结构 |
| --- | ---: | --- |
| `0x0000..0x06BC` | 1725 | 115 × 15 字节战场出场记录 |
| `0x06BD..0x083D` | 385 | 胜败条件等文本缓冲区 |
| `0x083E..0x0859` | 28 | 战场元数据；首个 `u32` 是回合上限 |
| `0x085A..0x2859` | 8192 | 4096 × `u16le` 事件变量 |

### 115 条出场记录的分组

| 全局槽位 | 数量 | 来源/用途 |
| --- | ---: | --- |
| `0..14` | 15 | 我军出场槽 |
| `15..34` | 20 | 友军；对应 S 剧本 `0x46` 的 20 项 |
| `35..114` | 80 | 敌军；对应 S 剧本 `0x47` 的 80 项 |

空槽的 `person_id` 为 `0xFFFF`。本地 `S_00.eex` 的 11 名友军和 14
名敌军，能按上述槽号逐条对应 `Sv00e.e5s`；人物编号、坐标、AI 类型和
等级均一致。它们在 `Sv00s.e5s` 的 26 字节运行时单位表中也占同一槽号。

15 字节记录为：

| 相对偏移 | 类型 | 含义 |
| ---: | --- | --- |
| `+0x00` | `u32le` | `person_id`；空槽为 `0000FFFF` |
| `+0x04` | `u8` | 初始横坐标 |
| `+0x05` | `u8` | 初始纵坐标 |
| `+0x06..0x09` | `u32le` | 出场方向、阵营和隐藏组合位 |
| `+0x0A` | `u8` | `ai_type` |
| `+0x0B..0x0C` | 2 字节联合体 | AI 附加参数；见下文 |
| `+0x0D` | `u8` | 运行时最大兵力参数 |
| `+0x0E` | `u8` | 等级 |

其中 `+0x0D` 会把剧本中的默认值 `FFFF` 物化成运行时值；例如
`S_00.eex` 的默认值在当前存档中为 2。`+0x0E` 则等于 Data 基础等级
加剧本 `people_lv`，例如刘备 `1 + 6 = 7`。

`+0x06..0x09` 由旧引擎作为一个 `u32le` 读写。原版存档的高 24 位恰好
全为零，不能因此把它们误标为三个独立保留字节。当前低字节可拆成：

- 方向 one-hot 位：方向 0/1/2/3 分别为 `0x20/0x08/0x40/0x10`
- 低三位：敌军常为 `1`，可见友军为 `2`，隐藏友军为 `6`

例如 `S_00` 中隐藏、方向 3 的刘备为 `0x10 + 0x06 = 0x16`；可见、
方向 0 的步兵为 `0x20 + 0x02 = 0x22`；敌军方向 2 为
`0x40 + 0x01 = 0x41`。这组换算已覆盖当前样本中的全部非空出场记录。

`+0x0B..0x0C` 对应运行时记录的 `+0x0E..0x0F` 两字节联合体。本地
`Ekd5.exe` 在执行出场指令时按 `ai_type` 分支写入：

- `ai_type` 为 3 或 5：把剧本中紧随 AI 类型后的第一个 `02 00 + u16`
  参数整体写入这两个字节；
- `ai_type` 为 4 或 6：分别取随后两个 `04 00 + u32` 参数的低字节，
  写入 `+0x0B`、`+0x0C`；
- 其他 AI 类型不写这一区域，保留初始化值。

因此它不是填充区，而是 AI 类型相关的附加参数联合体。原版脚本中类型
4/6 的非零值呈坐标形态，但在没有更多旧引擎消费路径证据前，解析器使用
中性的 `ai_parameter` / `ai_parameter_bytes` 名称，不直接套用新引擎
对 AI 类型的命名。

以上物理布局由本地旧引擎存档函数 `0x00417C84` 的 115 次循环直接确认：
它依次写出运行时记录 `+00` 的 4 字节、`+04/+05`、`+08` 的 4 字节、
`+0C`、`+0E` 的 2 字节、`+10/+11`，合计正好 15 字节。出场指令
`0x46/0x47` 的构造路径位于 `0x004128A7` 和 `0x00412CC6`。

文本区随存档语言变化：中文槽使用 GBK，日文槽使用 Shift-JIS。元数据
首四字节与同槽 `Sv??s[0x26]` 的回合上限逐一相符（20 或 30）。

最后 8192 字节恰好是 4096 个 `u16le` 槽。非零下标与 EEX
`true_var/false_var` 使用的变量编号体系一致，末端 `4084..4095` 又是
社区资料所称的系统保留变量区，因此应按“4096 个事件变量”解析，而不是
无结构的状态字节。

## `Svcmn.e5s` 公共状态

文件固定大小为 108 字节：

| 偏移 | 含义 |
| ---: | --- |
| `0x00` | 红线结局鸟标志 |
| `0x01` | 黄线结局鸟标志 |
| `0x02` | 蓝线结局鸟标志 |
| `0x03 + item_id` | Data 物品对应的图鉴状态字节 |
| `0x6B` | Logo 花色选择：`0..3` 为花色 1～4，`4` 为“无” |

原版特殊宝物从 Data 物品 ID 21 开始，因此第一个有效宝物图鉴字节位于
`0x18`。当前样本解锁了：

- `0x1A`：物品 ID 23，倚天剑
- `0x4F`：物品 ID 76，太平清领道

这与日文版逐地址宝物表一致。

### `0x6B` 的旧引擎调用证据

该字段已由本地 1999 年旧引擎 `Ekd5.exe` 的调用点定名，不依赖 Star
新版资料：

- `0x41A284` 是读取 `Svcmn.e5s` 指定字节的函数，
  `0x41A1B0` 是对应写入函数。
- `0x40B088` 固定读取偏移 `0x6B`，再把数值交给菜单对象。
- 本体字符串表把 `0、1、2、3` 映射为“花色１～花色４”，其他值显示
  “无”。
- 设置函数 `0x40AF77` 在数值小于 4 时读取 `Logo.e5`，选取的分块号
  是 `8 + value`；大于等于 4 时不加载花色图。
- 同一函数仅在保存标志开启时把当前值写回 `Svcmn[0x6B]`。

本地样本值为 `3`，即“花色4”，对应 `Logo.e5[11]`。轩辕春秋 2004
年全宝物存档的两份 108 字节附件彼此完全相同，末字节都是 `4`，即
“无”；这也说明它与结局数、宝物数和校验值无关。

## 解析实现

[`legacy_resource_formats.py`](https://github.com/lometsj/ccz_eex_parse/blob/master/legacy_resource_formats.py)
提供：

- `parse_main_save`：自动识别 21724/21709 字节布局，解析两种
  `Sv??d.e5s`
- `parse_battle_save`：解析 `Sv??s.e5s`
- `parse_extended_save`：分区解析 `Sv??e.e5s`
- `parse_svcmn`：结合 Data 物品表解析公共图鉴状态

批量导出命令：

```bash
./venv/bin/python tools/export_remaining_resources.py \
  /path/to/ccz /path/to/output
```

无法安全解释的附加原始区会以十六进制原样保存在 `analysis.json`；
已经定名的记录字段则使用稳定字段名导出。

## 结论

存档类文件当前状态：

- `Sv??d.e5s`：已确定中文 45 字节头和日文 30 字节头两种布局，
  两者逻辑偏移相差 `0x0F`；人物表均已完整解析。
