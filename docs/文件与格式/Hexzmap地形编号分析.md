# Hexzmap 地形编号分析

## 结论

`Hexzmap.e5` 的每个地图分块在前两个长宽字节之后，以先横后纵的顺序保存

## 证据

### 1. 主程序中的名称表

当前 `Ekd5.exe` 从文件偏移 `0x8ADE4` 开始，连续保存以下 GBK 字符串：

```text
平原 草原 树林 荒地 山地 岩山 山崖 雪原
桥梁 浅滩 沼泽 池塘 小河 大河
栅栏 城墙 城内 城门 城池 关隘 鹿砦 树木
兵营 民居 宝物库 水池 火 船 祭坛 地下
```

这30项紧邻兵种名称表，顺序与游戏地形编号表一致。

### 2. Hexzmap 的实际编号范围

解包全部58个 `Hexzmap` 分块后：

- 所有格值都在 `0x00..0x1D` 范围内。
- 没有任何未知编号。
- `0x00`、`0x01` 分别与社区格式资料确认的平原、草地/草原吻合。
- 稀有编号的位置和地图题材吻合，例如 `0x1D` 只在地下地图 `Hm57` 出现。

### 3. Data.e5 的30项地形属性

`Data.e5` 对每个兵种保存：

- 30字节地形能力修正；
- 30字节地形移动消耗。

这与主程序名称表及 `Hexzmap` 的30种编号构成同一索引空间。

## 解析方式

```python
columns = block[0] // 3
rows = block[1] // 3
terrain_ids = block[2:]

terrain_id = terrain_ids[y * columns + x]
terrain_name = TERRAIN_NAMES[terrain_id]
```

项目中的正式映射及校验函数位于：

- `battle_terrain.py`

可视化编辑器：

```bash
./venv/bin/python run_battle_map_editor.py /path/to/ccz
```

编辑器把 `HmXX.e5` 作为背景图、把本文件的逐格编号作为48×48网格层。保存时
只重建 `Hexzmap.e5`，先将新文件重新解包校验，再原子替换；首次保存会生成
`Hexzmap.e5.bak`。

## 资料交叉验证

- [MapMaster 工具开发讨论](https://xycq.org.cn/forum/thread-218062-1-9.html)：
  确认分块前两字节为宽高乘3、后续按先横后纵保存地形编号，并明确
  `00` 为平原、`01` 为草地。
- [曹操传运行时内存数据分析](https://www.xycq.org.cn/forum/viewthread.php?tid=196345)：
  确认每个兵种具有前30字节地形效果和后30字节移动消耗。
