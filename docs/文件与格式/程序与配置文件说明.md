## 主程序与运行库

### `Ekd5.exe`

- 游戏主程序/引擎
- `PE32 executable`

### `mp3serv.dat`

- 名字虽然是 `.dat`
- 实际上是 `MZ/PE` 可执行文件
- 用于 MP3 播放相关功能

### 其他 DLL

高可信用途如下：

| 文件 | 用途 |
| --- | --- |
| `AutoDLL.dll` | 自动存档、快速点击等补丁功能 |
| `Cmdicon.dll` | 菜单图标资源 |
| `Itemicon.dll` | 物品图标资源 |
| `Mgcicon.dll` | 策略图标资源 |
| `Mapatr.dll` | 地形属性图标 |
| `Koeicda.dll` | 把旧引擎 CD Audio API 转接到 `mp3serv.dat` 的兼容 DLL |

其中四个图标 DLL 已确认不是业务代码库，而是只含 `RT_BITMAP` 的 PE
资源容器：

| 文件 | 位图结构 | 编号映射 |
| --- | --- | --- |
| `Itemicon.dll` | 105 对 16×16/32×32 | `100/101 + item_icon_id×2` |
| `Mgcicon.dll` | 31 对 16×16/32×32 | `100/101 + magic_icon_id×2` |
| `Cmdicon.dll` | 4 张 16×16 | 100～103：攻击、策略、道具、待命 |
| `Mapatr.dll` | 28 张 48×48 | `100 + terrain_id`，对应地形 0～27 |

四者都使用未压缩 8-bit DIB，语言 ID 1041，调色板前 174 色与游戏固定
色区一致。完整资源表、EXE 调用证据和导出命令见
[`图像资源文件说明.md`](图像资源文件说明.md)。

### `Koeicda.dll` 与 `mp3serv.dat`

本地 `Koeicda.dll` 的 PE 时间戳为 2003-08-04，晚于 1999 年的
`Ekd5.exe`。它不是 Star 新引擎组件，而是保留旧引擎 CD 播放接口的
MP3 转接补丁。

DLL 导出 20 个旧式 `CDAudio*` 名称，序号 1～20：

```text
CDAudioClose             CDAudioEjectMedia
CDAudioGetDriveLetter    CDAudioGetNumDrives
CDAudioGetNumTracks      CDAudioGetPlayingPos
CDAudioGetStartPos       CDAudioGetTrackLength
CDAudioInitialize        CDAudioIsInserted
CDAudioIsPlaying         CDAudioNextPlay
CDAudioNextPlayTrack     CDAudioOpen
CDAudioPause             CDAudioPlay
CDAudioPlayTrack         CDAudioResume
CDAudioStop              CDAudioTerminate
```

其中只有四个播放控制导出有实际转接代码：

| 导出 | RVA | 转发动作 |
| --- | ---: | --- |
| `CDAudioPlayTrack` | `0x1110` | `PostMessage(hwnd, 0x1979, track, 0)` |
| `CDAudioStop` | `0x1160` | `PostMessage(hwnd, 0x1980, 0, 0)` |
| `CDAudioPause` | `0x10F0` | `PostMessage(hwnd, 0x1982, 0, 0)` |
| `CDAudioResume` | `0x1140` | `PostMessage(hwnd, 0x1983, 0, 0)` |

其余 16 个名称全部指向 RVA `0x1180`，只返回 1，是为满足旧引擎
动态取函数地址而保留的成功桩。`CDAudioPlayTrack` 从调用栈第二个参数
取得曲目号；函数本身使用普通 `ret`，由调用方清理参数，属于 C 风格
调用约定。

转接流程也能由 DLL 本身完整复原：

1. 用窗口类 `TTWinampPlayerForm`、标题 `MP3Serv` 查找播放器。
2. 首次找不到时执行同目录的 `Mp3SERV.DAT`，等待其输入队列空闲。
3. 再以窗口类 `TTWinAmpPlayerForm` 查找窗口并缓存句柄。
4. 之后四个有效导出用上述私有窗口消息控制曲目、停止、暂停和继续。

`Ekd5.exe` 内同时保存了 `koeicda.dll` 和 12 个它实际需要解析的
`CDAudio*` 名称，包括打开、初始化、播放曲目、停止、暂停、恢复及查询
曲目/位置。因此这个 DLL 的职责不是直接解码 MP3，而是把旧引擎原本的
CD Audio 调用转交给真正执行播放的 `mp3serv.dat`。

用 UPX 5.2.0 解包本地 `mp3serv.dat` 后，消息接收端也得到验证：

- 它注册隐藏窗口类 `TTWinampPlayerForm`、标题 `MP3Serv`。
- `WM_CREATE` 时读取同目录 `mp3list.txt`，每行存入一个 28 字节
  `std::string` 槽组成的动态数组。
- `0x1979` 把 `wParam` 当作旧 CD 音轨号；只接受 `2..曲目数`，
  用 `track - 1` 选择列表项。这解释了 `mp3list.txt` 第一行必须为空：
  CD 第 1 轨原本是数据轨，音乐从第 2 轨开始。
- 选中的相对路径交给 COM 媒体播放对象；程序导入
  `CoInitialize/CoCreateInstance`，实际解码由系统媒体组件完成。
- `0x1980/0x1982/0x1983` 分别调用该对象的 Stop/Pause/Run；
  `0x1981` 在当前接收端为空操作。

原始文件是 UPX 1.24 标记的 PE32，压缩大小 29,184 字节，解包后
57,344 字节。解包只用于分析，游戏目录仍保留原始压缩文件。

## 配置文件

### `AutoDLL.ini`

本地文件与本地旧引擎 `AutoDLL.dll` 的机器码可以一一对应：

| 段/键 | 默认值 | 旧引擎中的实际含义 |
|---|---:|---|
| `[DEFAULT] EnableAutoSave` | `0` | 是否执行自动存档补丁；非 0 视为开启 |
| `[DEFAULT] EnableFastKey` | `0` | 是否安装快速点击热键；非 0 视为开启 |
| `[FastKey] HotKey` | `32`（INI 未写时） | Windows 虚拟键码；32 即空格键 |
| `[FastKey] DelayTime` | `10` ms | 自动点击循环的等待时间 |
| `[AutoSave] AutoSaveSlot` | `10` | 1～10 号存档位；内部减 1 使用，越界回退到第 10 位 |

DLL 先用 `GetModuleFileNameA` 取得自身路径，把文件名替换为
`AutoDLL.ini`，然后用 `GetPrivateProfileIntA` 读取上述配置。

### `AutoDLL.dll`

本地文件是 2003-08-10 时间戳的 PE32 补丁 DLL，导出仅有：

| 导出 | RVA | 作用 |
|---|---:|---|
| `ASave` | `0x12B0` | 本地 `Ekd5.exe` 自动存档分支的跳板 |
| `dummy` | `0x12A0` | 仅 `ret` 的空桩；本地主程序没有导入它 |

本地 `Ekd5.exe` 自带 `.Silvana` 补丁节，并通过导入地址
`0x004CD014` 导入 `ASave`。主程序 `0x0044E1CD` 已被改为
`jmp [0x004CD014]`，所以这不是可跨版本套用的抽象插件接口，而是与
该旧引擎固定代码地址绑定的二进制补丁。

`ASave` 保留原分支标志：

- 原条件不满足时跳回 `0x0044E1D3`；
- 进入自动存档路径时，若 `EnableAutoSave=0`，直接续接
  `0x0044E6EE`；
- 开启时调用旧引擎存档函数 `0x0041B16A(slot_index)`；
- 调用前临时把 `0x0041B1F4`、`0x0041B4E7` 的两个 `call` 改为
  NOP，并把 `0x0041B1FE` 的 `jne` 改为 `jmp`，调用后逐字节恢复。
  这表明补丁是在复用旧引擎正常存档流程，同时绕开交互/提示分支，
  不是自行实现 `.e5s` 写盘格式。

快速点击路径同样已由机器码闭合：

- `EnableFastKey!=0` 时安装 `WH_KEYBOARD`（类型 2）钩子；
- 键盘按下配置的 `HotKey` 时切换快速点击状态，默认键为空格；
- 工作线程按 `DelayTime` 睡眠，查找窗口类名
  `三国志曹操传`；
- 开启状态下依次向该窗口发送 `WM_LBUTTONDOWN (0x0201)` 和
  `WM_LBUTTONUP (0x0202)`，两条消息的 `wParam/lParam` 都为 1，
  中间固定等待 10 ms；
- DLL 卸载时终止循环并解除钩子。

以上地址和行为只适用于仓库内这份旧引擎程序；Star 或其他带版本号
引擎的补丁地址不能据此类推。

### `font.reg` / `font2.reg`

- Windows 注册表脚本
- 用于字体相关配置

### `mp3list.txt`

- 背景音乐列表
- 逐行列出 `SoundTrk` 下的 MP3 文件

## 结论

本类文件大多不需要逆向图像/脚本结构，但需要知道它们在资源体系中的职责：

- 哪些是程序主体
- 哪些是资源容器 DLL
- 哪些是补丁/配置

目前四个图标 DLL 已达到可稳定解析和导出的程度，`Koeicda.dll` 的
导出表和与 `mp3serv.dat` 的窗口消息协议、`AutoDLL.dll` 的自动存档
跳板和快速点击路径也都已由本地旧引擎机器码确定。`mp3serv.dat` 的
UPX 层、曲目表索引和窗口消息接收实现已经闭合。
