# 数据与文本文件说明

## 范围

本类文件主要包括：

- `Data.e5`
- `Imsg.e5`

## `Data.e5`

### 用途

`Data.e5` 是游戏主数据表来源，现有脚本已能从中抽取：

- 人物数据
- 物品数据
- 商店数据
- 兵种数据
- 地形数据
- 策略数据

### 逻辑结构

[`ccz_origin.json`](https://github.com/lometsj/ccz_eex_parse/blob/master/ccz_origin.json) 中已整理出主要偏移：

| 项目 | 偏移/数量 |
| --- | --- |
| 人物 | `0x18C` / `0x200` |
| 物品 | `0x418C` / `0x68` |
| 商店 | `0x4BB4` |
| 兵种 | `0x53DC` / `0x35` |
| 地形 | `0x5973` |
| 策略 | `0x5FC7` / `0x44` |

### 物理格式

旧引擎可以识别两种 `Data.e5` 物理形态：

- `Ls12` 分块容器；
- 将各分块按编号顺序连接得到的线性解压负载。

本地原版样本采用 `Ls12`，但解压后的线性版本也可直接交给游戏主程序。
编辑器因此把两种形态都视为合法输入和输出，而不是把解压版报告为损坏。

已确认 10 个分块：

| 分块 | 长度 | 结构 |
| ---: | ---: | --- |
| 0 | 16384 | 512 × 32 人物 |
| 1 | 2600 | 104 × 25 物品 |
| 2 | 2088 | 58 × 36 商店 |
| 3 | 1431 | 53 × 27 兵种 |
| 4 | 1620 | 27 × 60 兵种大类地形表 |
| 5 | 5110 | 73 × 70 策略 |
| 6 | 8704 | 512 × 17；人物数量对齐的未使用文本占位表 |
| 7 | 1768 | 104 × 17；物品数量对齐的未使用文本占位表 |
| 8 | 1156 | 68 × 17；有效策略数量对齐的未使用文本占位表 |
| 9 | 1218 | 58 × 21；关卡数量对齐的未使用文本占位表 |

解压后总负载长度为 `42079`。分块 6～9 的物理边界已确定，原版样本
内容均为“终端”加零填充；进一步核查本地 1999 年旧引擎后，已确认
这四块不会被原版运行时装载。

### 与现有偏移体系的关系

`Data.e5` 解压后的主负载与原偏移体系的关系是：

```text
解压后有效偏移 = 配置偏移 - 0x18C
```

例如：

| 配置偏移 | 解压后偏移 |
| --- | --- |
| `0x18C` | `0x0000` |
| `0x418C` | `0x4000` |
| `0x4BB4` | `0x4A28` |
| `0x53DC` | `0x5250` |
| `0x5973` | `0x57E7` |
| `0x5FC7` | `0x5E3B` |

这说明现有偏移体系的分块起点有效，只是针对“带前导区的逻辑视图”。
但旧 `parse_data.py` 把地形表循环次数写成 53，实际应是 27 个
`ForceCategory`。每条前 30 字节是地形适应值，后 30 字节是移动消耗；
旧循环会越过 1620 字节分块并误读策略表。

### 地形表的重要修正

旧逻辑从配置偏移 `0x5973` 开始循环 53 次，每次读取 30 字节适应值和
30 字节移动值。这个解释不成立：

```text
53 × 60 = 3180
实际地形分块只有 1620 字节
```

正确结构为：

```text
27 个 ForceCategory
每类 30 字节地形适应值（8..12 表示 80%..120%）
随后 30 字节移动消耗（1、2、3 或 FF 不可通行）
27 × (30 + 30) = 1620
```

27 正好对应 `ccz_origin.xml` 的 27 个 `ForceCategory`。新解析器严格按
Ls12 分块边界读取，不会越界进入策略表。

### 策略表

物理上有 73 条，每条 70 字节：

```text
11 字节名称
type, effect_target, hitarea_id, effarea_id, mp_cost, icon_id
53 个兵种学习等级
```

配置声明的有效策略数是 68；后五条确实命名为“空白１”～“空白５”，应
作为保留槽暴露，而不是从物理解析中丢弃。

### 前六个业务表的解析字段

[`legacy_resource_formats.py`](https://github.com/lometsj/ccz_eex_parse/blob/master/legacy_resource_formats.py)
中的 `parse_data_e5` 会解析：

- 人物：名称、头像、R 形象、暴击台词、阵营、五维、HP/MP、兵种、等级和装备
- 物品：名称、类型、特殊效果、价格、图标、基础/升级值和宝物标记
- 商店：仓库/商店触发人物、16 个装备槽和 16 个消耗品槽
- 兵种：移动力、攻击范围、成长值和 18 个物品类别使用标志
- 地形：27 类的 30 个适应值与 30 个移动消耗
- 策略：名称、类型、目标、攻击/效果范围、MP、图标和 53 个学习等级

### 分块 6～9：旧引擎未使用的占位表

这四块不能仅凭记录数把它们命名为人物/物品/策略/关卡的真实业务字段。
本地旧引擎的静态调用证据为：

- `Ekd5.exe` 中 `0x41B51E` 是按编号读取 `Ls12` 分块的通用函数。
- `Data.e5` 初始化入口 `0x41B639` 依次调用六个加载函数，请求的块号是
  `0、1、3、4、2、5`，即只装载前六个业务表。
- 全程序其余 `0x41B51E` 调用中，两个固定请求仍为块 0；另外两个动态
  参数来自 `0x40E090`，该函数调用随机数例程并把范围限定为 `0..3`。
- 因而本地旧引擎不存在请求块 6、7、8、9 的调用路径。

文件内容也与“不使用”结论一致：

- 记录数与记录长度已经验证
- 所有记录内容均为 GBK“终端”加零填充
- 四块分别只是在数量上对齐人物、物品、有效策略和关卡

解析器仍保留这些物理记录，以免重打包时丢失；但将它们标为
`loaded_by_local_old_engine = false`，不把“可能给制作工具或未完成设计
预留”提升为已证事实。

### 导出与校验

批量解析命令：

```bash
./venv/bin/python tools/export_remaining_resources.py \
  /path/to/ccz /path/to/output
```

输出 `analysis.json` 会包含全部 512 人物、104 物品、58 商店、53 兵种、
27 地形类别、73 策略，以及后四个辅助表的记录边界摘要。

## `Imsg.e5`

### 用途

`Imsg.e5` 是文本/说明库，承载：

- 人物介绍
- 兵种说明
- 物品说明
- 策略说明
- 战役名称
- 人物列传
- 撤退台词
- 致命一击台词
- 制作人员表

### 物理格式

`Imsg.e5` 不属于 `Ls12` 家族，也不是可变长文本流。原版文件结构为：

```text
文件大小 = 184200
记录大小 = 200
记录数量 = 921
编码 = GBK，首个 NUL 结束，其余字节补零
```

本地 921 条记录全部满足：

- 可按 GBK 严格解码
- 首个 NUL 后全为零
- 最长有效记录为 160 字节
- 文件中没有实际 CR/LF 字节；6 条多行台词使用两个 ASCII 字符 `\n`
- 编辑时编码后最多允许 199 字节，必须留下 NUL 终止符

### 八个文本区

配置偏移全部是 200 的倍数。七条英文标记记录分隔出八个区：

| 区域 | 配置起点 | 数据记录数 | 原版有效数 | 后续标记 |
| --- | ---: | ---: | ---: | --- |
| 物品说明 | `0x00000` | 149 | 104 | 全局记录 149 |
| 策略说明 | `0x07530` | 99 | 68 | 全局记录 249 |
| 战役名称 | `0x0C350` | 99 | 58 | 全局记录 349 |
| 兵种说明 | `0x11170` | 98 | 53 | 全局记录 449 |
| 原版人物列传 | `0x15F90` | 199 | 174 | 全局记录 649 |
| 撤退台词 | `0x1FBD0` | 49 | 26 | 全局记录 699 |
| 致命一击台词 | `0x222E0` | 99 | 51 | 全局记录 799 |
| 制作人员 | `0x27100` | 121 | 107 | 文件结束 |

“数据记录数”不包含区尾英文标记。原版有效记录之后的空余槽内容为
“终端”。兵种区的全局记录 448 是一条导入来源注释，不属于 53 条兵种
说明；记录 449 才是下一分区标记。

标记记录：

| 全局记录 | 偏移 | 内容 |
| ---: | ---: | --- |
| 149 | `0x7468` | `Magic Message Start` |
| 249 | `0xC288` | `Hex Battle Name Start ( MAX : 18 Bytes )` |
| 349 | `0x110A8` | `Unit Message Start` |
| 449 | `0x15EC8` | `Personal History Message Start` |
| 649 | `0x1FB08` | `Retire Message Start ( Team Unit Only )` |
| 699 | `0x22218` | `Critical Attack Message Start` |
| 799 | `0x27038` | `Staff Roll Start...` |

配置中的 `Imsg_UnitExtension_Offset = 0x2D050` 比当前文件末尾
`0x2CF88` 大 200 字节。它属于扩展引擎预留逻辑；当前原版文件没有人物
扩展区，不能直接按该偏移读取。

### 编号映射

- 物品说明 `i` 对应 Data 物品 `i`，原版使用 0～103。
- 策略说明 `i` 对应 Data 策略 `i`，原版配置使用 0～67；Data 的五条
  “空白”保留策略没有独立说明。
- 战役名称 `i` 对应战场/关卡 `i`，原版使用 0～57。
- 兵种说明 `i` 对应 Data 兵种 `i`，原版使用 0～52。
- 人物列传 `i` 对应 Data 人物 `i`，原版使用 0～173。
- 撤退区容量为 49 条，对应人物 0～48；当前原版文件只填写人物 0～25，
  即曹操到满宠。

### 致命一击台词

致命一击区前 51 条有两套选择机制。

前 21 条是特殊人物专属台词。`Ekd5.exe` 文件偏移 `0x89C30` 保存 21 个
`u32le` 人物编号：

```text
0, 1, 2, 3, 6, 7, 9, 13, 15, 16, 17,
33, 34, 36, 57, 84, 95, 108, 109, 119, 32
```

它们依次对应曹操、夏侯惇、张辽、关羽、夏侯渊、张郃、庞德、徐晃、
许褚、典韦、貂蝉、张飞、赵云、黄忠、马超、甘宁、太史慈、颜良、文丑、
吕布、刘备。特殊人物表优先于 Data 字段。

记录 21～50 是十组通用台词，每组三句：

```text
section_record = 21 + critical_text_type × 3 + random(0..2)
critical_text_type = 0..9
```

Data 人物记录 `+0x10` 的准确语义因此应为
`critical_text_type`，不是单条台词 ID。原版 174 人实际使用 0～8；
类型 9 的三条台词存在于 Imsg，但原版 Data 未引用。

### 制作人员区

制作人员区不是普通“编号对应文字”，而是简单控制语言：

- `//n`：页编号/注释
- `%文字`：职务标题，最大 26 字符
- 普通文字：人员姓名
- `;`：下一页，标记说明最大 12 字符

当前有效记录为 0～106，组成原版制作人员页面；107～120 为“终端”。

### 解析和安全回写

实现：

- [`imsg_resources.py`](https://github.com/lometsj/ccz_eex_parse/blob/master/imsg_resources.py)
- [`tools/export_imsg.py`](https://github.com/lometsj/ccz_eex_parse/blob/master/tools/export_imsg.py)

导出：

```bash
./venv/bin/python tools/export_imsg.py \
  /path/to/ccz /path/to/imsg-analysis.json
```

`imsg_resources.replace_record` 只替换一个 200 字节槽，不移动后续数据，
会拒绝 NUL 和编码后超过 199 字节的文本。加载器同时校验文件长度、全部
记录补零规则和七个分区标记，适合保存后重新读取验证。

### 版本注意事项

上述布局针对当前 184200 字节原版文件。轩辕春秋 6.4/6.5 扩展引擎资料
提到 440200 字节 Imsg，并会移动撤退台词位置。因此扩展版不能硬套原版
偏移，解析前必须按文件大小和引擎配置选择布局。

## 结论

数据与文本类文件的工程重点应当分开：

- `Data.e5`：使用分块边界解析，尤其不要沿用旧地形表的 53 条循环
- `Imsg.e5`：按 921 个固定 200 字节 GBK 记录抽取和原位回写

`Data.e5` 已达到可稳定拆包和字段级导出的程度。分块 6～9 已确定为
本地旧引擎不装载的“终端”占位表；解析器保留其物理结构，不擅自推断
它们在开发期工具或其他引擎中的潜在用途。
