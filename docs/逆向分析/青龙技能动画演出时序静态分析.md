# 青龙技能动画演出与计时：静态分析

本文针对策略64（十六进制`0x40`），追踪原版的施法、召唤、逐发特效、数值安装及源MP结算。结论来自EXE反编译和原始资源字节；既有动态采样仅在末尾独立列出，不把静态分析写成运行观察。

分析版本：`Ekd5.exe`，x86 PE，SHA256 `c4228269bdc4d91a9db9a90c4dc9ff9a23df5333d9d0acdee98a51cba0111775`。分析日期2026-10-14，工具REA/Ghidra12.1.4。函数名`FUN_...`是反编译器命名，不是原始C++源码符号。

## 一、完整主路径

|阶段|原版函数|已确认行为|
|---|---|---|
|策略分发|`00425627`|设置伤害状态类别`0x40`，准备MCALL资源，进入青龙专用函数；退出后调用源结算`00422F0D`|
|青龙专用路径|`00424E9E`|初始点选验证；以施法者为中心建立候选池；一次施法动作、一次MCALL06；最多五发逐次抽取、计算、演出、安装|
|施法动作/名称|`004218D6`|聚焦施法者，处理方向、UNIT_ATK姿势、逻辑音效8/39、技能名称及补足等待|
|召唤|`00421879 → 00403014`|播放MCALL06，恢复底图，再预约4tick并等待|
|每发主特效|`004214BF → 00401E5C`|青龙跳过重复施法动作；选择MEFF22，执行控制字节、人物姿势/数字、逐帧播放及收尾等待|
|每发结算|`004224A8 → 00450984`|回避等附加表现、数值面板、实际HP/MP安装、自动豆、目标防具经验处理|
|源结算|`00422F0D → 00450984`|五发或候选池耗尽后处理源面板、MP、经验和武器经验|

候选池中的死亡目标在**再次被抽中**时以末项替换删除，不计入五发；非死亡目标的一次尝试计入发数，伤害为零也计次。下一发的抽取发生在上一发`004224A8`返回之后。初始点击的目标不保证是第一发目标。[E1]

青龙在调用`004218D6`前把`param[0xD]`换成施法者自身，因此召唤前聚焦施法者，自指方向路径保留已有朝向。MCALL中心为施法者屏幕坐标加`(24,24)`；每发MEFF则聚焦当发目标。[E1、E2]

## 二、时钟及取整

核心代码可概括为以下等价描述，非原始源码：

```text
now_tick()          = GetTickCount() / 50
set_wait(n)         = deadline = now_tick() + n
wait_until_due()   = 循环检查 deadline，期间处理消息，直至剩余时间为零
resource_ticks(ms) = unsigned_integer(ms) / 50
```

`0047EB97`明确整数除`0x32`；`00403340 → 0042C45F`从**当前tick**设置新截止时间，不是累加到旧截止时间；`0042C4E0 → 0042F7F0 → 0042C479`负责等待。[E3]

因此资源中的毫秒值向下取整：例如149ms转成2tick（标称100ms），150ms转成3tick（150ms）。100ms和150ms都恰好整除，本例两份资源没有余数损失。[E4]

这也不等于墙钟上的每次等待都精确为`n×50ms`。截止时间落在全局50ms边界上，调用时已处于当前tick的某个相位；消息处理、线程调度和绘制超时又可能使返回变晚。`0042C479`还使用有符号比较，不能据此声称已处理全部长时间运行/计数回绕边界。

MCALL/MEFF循环的顺序也值得保留：准备/绘制当前步，等待前一轮已经设置的deadline，再提交当前步并设置下一次deadline；结尾另有最后一次等待。不能简单实现成“绘制完以后无条件Sleep整段毫秒”，否则计算/绘制开销的重叠关系会不同。[E5]

## 三、施法动作和名称：并非固定一秒

`004218D6`先预约8tick，播放逻辑音效8，准备并提交施法姿势，然后等待到期；接着记录当前tick、播放逻辑音效39，调用名称显示，返回后计算：

```text
remaining = 20 - (now_tick() - name_start_tick)
if remaining > 0:
    set_wait(remaining)
wait_until_due()
```

也就是说，名称阶段**至少补足20tick预算**；若名称显示已经耗时超过20tick，不再额外等待20tick。[E2]

`0042F699(2) → 0042F433`绘制名称后读取配置对象`004B0770 + 0x10`的字节`s`，调用`0042C646((s+1)×10)`。后者每轮通过`0042C4CB(1)`预约**2tick**，而不是1tick，并允许输入检查提前退出。因此，在不提前退出且不超时的理想情况下，这个内部名称等待预算是`(s+1)×20tick`；外层再补足至少20tick。[E6]

本文未把配置字节的全部合法取值和界面名称猜成固定速度枚举。名称实际耗时、提前退出输入和系统开销会影响完整施法时间。

## 四、MCALL06：召唤资源与追加等待

原始资源为原始`Mcall06.e5`，头部20字节与全部21条20字节步骤已冻结到[资源摘要](dragon_animation_audit/resources.json)。

|字段|原字节解析|
|---|---:|
|步骤数 / A图数 / B图数 / 内嵌调色板数|21 / 21 / 0 / 0|
|每步毫秒 / 换算tick|150 / 3|
|图像尺寸|300×300|
|头部音效值|13|
|文件SHA256|`c8cf41d36a98fa4e22e3726709a20da40c3256ca08f8ea8f076ee19ed91e814d`|

无提前异常和慢帧时，资源本身的等待预算为`21×3=63tick`，标称3.15秒。`00421879`在播放后**另外等待4tick**，所以召唤路径的标称等待预算是67tick，即3.35秒，尚未包含施法文字、任何一发攻击或源MP结算。[E4、E5]

资源由`00402F7F`启动工作线程加载；播放前`0040284F`会等待线程完成，轮询含`Sleep(50)`。若仍未加载完成，会引入不固定的等待，不能计成恒定资源帧数。[E7]

每条步骤的`+0x10`是**一个控制字节**。MCALL06全部为0；`+0x11..0x13`中存在非零保留字节，不能把整个尾部DWORD当作控制码。该资源第一步满足自动声音条件，`00403147`传给音效系统的逻辑编号是`13+100=113`。这不是直接把头部13写成“SE13”。[E4、E8]

## 五、MEFF22：每发画面、姿势与数字

MEFF22从原始`Meff.e5`容器解压获取，不以PNG预览图反推运行行为。块SHA256为`d4834f2824caf68cccfa5c116ef0ed141db62a8bd0b8c0ecae2300e4aa84b753`。

|字段|值|
|---|---:|
|步骤数 / A图数 / B图数 / 内嵌调色板数|8 / 7 / 0 / 0|
|每步毫秒 / tick|100 / 2|
|尺寸|80×90|
|头部音效值 / 首步逻辑音效编号|18 / 118|

|步骤（从0计）|图像编号|暗化 / 不透明度参数|偏移(x,y)|控制字节|
|---:|---:|---|---|---:|
|0|0|16 / 7|(0,-26)|0|
|1|1|16 / 16|(0,-26)|0|
|2|1|16 / 8|(0,-26)|0|
|3|2|16 / 16|(0,-23)|0|
|4|3|16 / 16|(0,-13)|1|
|5|4|16 / 16|(0,-11)|0|
|6|5|16 / 16|(0,-11)|0|
|7|6|16 / 16|(0,-11)|0|

这里“8步”不等于“8张不同图像”。步骤4控制字节1经`00401E5C → 00421F04`触发人物反应和数字绘制：命中伤害类别匹配`0x40`时采用UNIT_SPC偏移`0x1B00`（姿势3），正HP伤害数字采用颜色索引`0x12=18`，数字偏移参数`0x18=24`。标称触发位置是在此前四个步间隔之后，约400ms；实际可见提交点还受前述等待/绘制顺序影响。[E9]

控制字节3可触发声音；首步也可自动触发声音，首步控制2会抑制该自动条件。本资源只有步骤4为1、其余为0，因此正常每发只自动触发一次逻辑音效118。[E8]

MEFF播放器还检查输入：一旦`0042C56B`返回非零，内部标记关闭后续循环中的逐帧等待。不能声称所有输入情况下都严格播放`8×100ms`；青龙主特效的非空战斗上下文收尾路径仍有最后deadline等待及底图恢复。[E5、E9]

## 六、每发额外等待与面板

`004214BF`播放MEFF后刷新目标，设置`min(20,5+5×目标数)`tick等待。青龙每次只安装一个当发目标，因此这里是**10tick=500ms**，而非五发一起算20tick。[E2]

接着进入`004224A8`。命中且有HP变化时，它先调用数值面板，再写入实际HP/MP，然后处理自动豆、防具经验与升级检查。伤害为零走回避MEFF45及8tick等待分支，不能套命中路径的固定时长。[E10]

面板`00450984`及其分支`00450036`也包含等待：

- 两栏分支、有HP/MP变化：五次1tick插值；最后等待4或8tick（由`param8`控制）。`param8=0`时合计9tick=450ms。
- 多栏分支、有HP/MP/人物经验变化：五次1tick插值，随后4tick，再最后4或8tick。
- 武器/防具经验非零时，多栏分支另有四次1tick插值；装备与经验上限可能改变哪些分支执行。
- 数据全零的两栏面板可直接不显示；不能把所有调用都机械增加同一面板时长。[E11]

因此，对本文限定的普通敌军、非零HP伤害、两栏面板`param8=0`、无额外豆/升级且未加速输入的路径，每发标称等待预算为：

```text
MEFF22 16tick + 组尾等待10tick + 目标面板9tick
= 35tick = 1.75秒
```

这是**带条件的静态推导**，不是所有命中/回避/自动豆/升级情况的统一常数。

## 七、五发后源结算与总预算

`00424E9E`在循环结束后设置成功标记；`00425627`随后调用`00422F0D`。后者先显示源面板，再写源MP、人物经验、武器经验并进行升级检查。源收益使用前面逐发累计的最大值，不是每发都显示一次源MP面板。[E1、E10]

玩家施法者仅MP变化且装备经验没有额外插值的源面板路径，预算为`5+4+8=17tick`，标称850ms。[E11]

将上述条件全部固定，并把名称阶段限定为20tick，五发名义等待预算为：

```text
施法8 + 名称20 + 召唤(63+4) + 五发(5×35) + 源面板17
= 287tick = 14.35秒
```

**14.35秒是该条件路径的名义预算，不是任意一次青龙从点击到可操作的保证时长。** 名称设置、输入提前退出、资源线程等待、绘制超时、回避、豆、升级和外层死亡对白都可能改变实际墙钟时间。本文没有把外层所有死亡/升级分支的调用者追踪宣称为完成。

## 八、与既有动态观察对照

此前2026-10-14的原版90秒/4500帧采样，目标顺序为`45→87→45→49→87`，五次HP安装间隔约1.74–1.76秒；末发HP安装后约840ms才安装源MP（121→81）。这与上述1.75秒目标路径和850ms源面板预算相符，但采样为50Hz顺序读取，不证明内部事件精确到毫秒。

该原版采样观测到RNG逐发推进。原版声音触发点在这里是静态结论，尚无对应录音校验。
