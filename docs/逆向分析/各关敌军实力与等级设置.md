# 各关敌军实力与等级设置

## 结论与阅读方式

原版58份S战场脚本没有给每关设一个固定敌军等级。**58关的全局等级参数都为52，即对出阵我军的截尾平均等级减2，再按每个敌军的个人参数加减。** 兵种进阶、人物基础属性、装备和剧情状态又分别影响实际实力。因此同一关在不同出阵队伍下，敌军等级与属性可以不同。

本文依据原版Ekd5.exe静态调用、58份S脚本原字节、Data.e5和Imsg.e5。下方每关均有独立明细，列出所有有效敌军槽、个人等级参数、初始隐藏/增援标志、原兵种ID、装备请求及后续条件索引。覆盖S00～S57，包括不同分支上的同名或相近关卡；它们不是要求一次通关连续经历的58战。

示例中A=20只是假设的比较基准，不是某条自然路线的推荐等级或实测等级。人数均为预配置槽位数，不能直接当作开场可见人数、一定登场人数或路线击杀数。

## 一、先取出阵名单的截尾平均

原函数`0x41885A`读取`0x48B350`的出阵名单，对人物等级排序。设人数n，`q=floor(n/4)`，去掉最高q人和最低q人，再对其余`n-2q`人求整数平均A。

```text
selected deployment roster
             |
             v
      sort unit levels
             |
             v
 discard q lowest + q highest
             |
             v
 A = floor(sum(middle) / (n - 2*q))
```

名单来自出阵选择与强制/禁止出阵项的处理，**不是全体已加入队伍的人物，也不是战场上当前存活或可见的我军**。例如8人等级为1、2、3、4、20、30、40、50，去掉两端各2人后，A为`floor((3+4+20+30)/4)=14`；直接算8人平均会得到另一个数。

最高级或最低级人物不一定能单独改变敌军等级，因为可能被裁掉；但改变出阵人数也可能改变q及中间组，不能用“只看某个人”概括。原平均函数没有空名单默认1的处理：其分母在n=0时为0，正常调用须有合法出阵名单。不要把招募时另一个平均函数的空队伍规则套到这里。

## 二、战场参数与个人参数分两次生效

### 1. 本关共同基准B

战场全局指令`0x45`的`people_lv`是偏移编码g：FFFF先按0；0～50表示加g，51以上表示减`g-50`。本地58关全为52，所以正常人物等级1～50范围内：

```text
B = max(1, A - 2)
```

底层先做低8位加法，再把结果当有符号字节检查，小于1时置1。对本地脚本52及正常等级，上式成立；它不是任意异常16位参数的通用整数公式。

### 2. 每个敌军的个人选择器p

敌军设定指令`0x47`的80个预设槽位各有`people_lv`。这个字段同样是偏移选择器，不是固定等级。FFFF先转0：

```text
p <= 50 : L = min(50, B + p)
p >  50 : L = max(1, B - (p - 50))
```

|个人参数|原版含义|A=20、B=18时|58份脚本有效槽数|
|---|---|---:|---:|
|0|沿用B|18|1661|
|FFFF|按0，沿用B|18|27|
|2|B+2，上限50|20|1|
|4|B+4，上限50|22|212|
|6|B+6，上限50|24|277|
|8|B+8，上限50|26|1|
|52|B−2，下限1|16|6|
|55|B−5，下限1|13|19|
|65|B−15，下限1|3|8|

必须先计算B，再应用p。在A=1时，B先置为1，p=6的敌军为7级；所以不能把“通常是A+4”写成所有情况下都成立的公式。在高等级端，加成又会被50级上限截断。Data.e5人物记录中的初始等级也不能直接当作本关敌军等级，它会被这条出场初始化链设置为L。

## 三、什么时候确定等级：隐藏增援会不会跟着升级

`0x4129A4`处理一整条`0x47`时，先调用一次平均函数，然后给各有效敌军槽计算L并写入部署缓存。58份本地S脚本每份恰好有一条该指令，都在Scene 0、Section 0，且没有子条件包裹；敌军指令内固定80槽，FFFF人物ID为空槽。

随后战场初始化`44D427 → 44CC85`为有效记录恢复人物基础数据、设置等级/兵种/装备，并将含装备的HP/MP填满。**初始隐藏不跳过这一初始化过程**；只是控制是否把单位放入地图占位。后来显示已经初始化的隐藏部队，不会因此自动重新取平均；若重新执行整条敌军设定指令，才又读取当时名单中的等级。

因此在战场中我军升级、减员或某个敌人显现时，不能据此推断本关敌军会全面即时追随等级。隐藏标志与增援标志也不相同：58关有效槽里有686个初始隐藏标志，但只有5个显式增援标志；许多剧情后续登场人员是通过隐藏和后续显示指令安排的。

## 四、相同等级为什么实力不同

### 兵种进阶与章节进度

原敌军记录的字段`max_troop`在这里控制**兵种进阶上限模式**，不是兵力上限。2212个有效敌军槽全部使用FFFF，原指令将其归一为模式2。

人物ID不超过173时使用脚本模式；ID大于173的通用人物由章节进度原值覆盖：章节进度0用模式0，章节进度1用模式1，章节进度2或3用模式2。这个值来自章节标题指令0x67：原413B3D将章节号减1，经418C70写入经理+6；409560读取同一字节，存档对应manager_raw[11]。所以它是章节进度，不是另一个难度选项。

原兵种ID小于39时：

|模式|L≤14|15≤L≤29|L≥30|
|---|---|---|---|
|0|原兵种|原兵种|原兵种|
|1|原兵种|原兵种ID+1|原兵种ID+1|
|2|原兵种|原兵种ID+1|原兵种ID+2|

原兵种ID不小于39的特殊兵种不套用上述递增。`442890`这条链中没有给章节进度另加若干人物等级；章节进度改变进阶，会连带改变成长、射程、移动和可用装备等兵种性质，故不能用“章节进度没加等级，所以没加实力”判断。

### 基础属性、成长与装备

等级L设置后，`442890 → 4089CB → 406E17`从原人物基础值加上累计成长。前5项属性饱和上限255，HP上限500，MP上限250；进阶兵种的成长有分段，不能统一写成`(L−1)×最终兵种成长`。不同人物原始基础属性不同，所以同级、同兵种也不一定一样强。

普通自动武器/防具由`407FE7`按最终兵种的首个可用类别与人物等级选取：

```text
ordinary equipment tier  = min(2, floor(L / 12))
ordinary equipment level = floor((L % 12) / 4) + 1   if L < 36
                         = 3                        if L >= 36
```

装备阶数从0计，与物品表条目选择相关；人物等级12、24会切换普通装备档次，档次内还会在相应4级边界提升装备等级；36级以后保持普通装备等级3，不再按余数从1循环。辅助槽没有同样的自动普通配装分支。

剧本`0x48`可以覆盖装备。原参数FFFF先归一为0；0自动，1清空，合法的2以上参数请求指定物品，还须符合槽位类别与兵种兼容性。转换到Data物品ID的偏移分别为：武器−2、防具+36、辅助+51。逐关表列出的是**请求**，有条件的指令不保证在每个分支执行，非法或不兼容请求不能当作必定装备成功。

武器/防具的装备等级字段FFFF先按0（自动计算）；显式装备还区分普通3级上限与特殊9级上限，不能把人物等级或脚本原参数直接当作装备等级。完整原消费函数与装备成长记录见证据附件。装备之后还会重新取HP/MP上限并设满。

后续的状态、HP/MP、AI、显示、撤退、复归及地形位置会进一步影响战斗表现。逐关JSON保留这类指令的地址和条件链，不能把它们与等级初始化合成一个“敌军总战力”分数。
