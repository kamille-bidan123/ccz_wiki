# 曹操传旧引擎战场 AI 行动与价值分析

## 1. 适用范围与证据口径

本文只分析仓库内 `ccz/Ekd5.exe` 对应的 2003 年旧引擎。编号、地址和
数值均以本地主程序、原版 `S_*.eex` 与战场存档为第一证据；轩辕春秋
原版实测文章用于解释函数用途和补足尚未完全符号化的分支。Star 及带
版本号的新引擎资料不用于给本地旧引擎直接定名。

本文使用三级结论：

- **已核实**：本地机器码、数据表或原版剧本分布可直接证明；
- **高可信**：原版实测结论与本地控制流、常量和字段相互吻合；
- **待动态验证**：已有原版实测现象，但尚未把全部机器码分支还原成
  可独立运行的评分器。

## 2. 敌军回合不是逐格“即时思考”

旧引擎的自动行动可概括成以下流水线：

1. 按阵营阶段建立自动行动队列；
2. 按单位记录中的 `action_order` 逐号扫描；
3. 跳过未在地图、AI 类型为 7（内部禁用值）、已经移动或已经行动的
   单位；
4. 根据 AI 类型确定激活条件或战略目的地；
5. 枚举可达格、物理攻击、可用策略和纯站位候选；
6. 给每个候选计算“行动价值 + 站位价值”，选择最高值；
7. 按固定规则处理同分，执行移动和行动，并写回运行标志。

主调度循环位于 `0x0044E9BF..0x0044EBEF`。它检查：

- 单位上场状态必须为 2；
- `0x00425AB0` 返回的行动顺序必须等于当前扫描序号；
- `0x00425AD0` 返回的 AI 类型不能为 7；
- `0x00425AF0` 检查 `has_moved(0x04)` 和 `has_acted(0x02)`。

旧引擎的 115 个单位槽固定分为：

- `0..14`：我军；
- `15..34`：友军；
- `35..114`：敌军。

调度代码也以 `0x23 = 35` 为阶段边界。这里的 AI 单位不会简单地按人物
ID 行动，而是由战场初始化时生成的 `action_order` 决定顺序。

## 3. 七种 AI 类型

文件和 EEX 实际保存的类型是 `0..6`。社区文章常把它们写成第 1～7
类，因此阅读旧资料时需要减一：

| 原始值 | 本文名称 | 行动机制 |
| ---: | --- | --- |
| 0 | 被动出击 | 物理攻击范围内出现敌人后才激活；文官也按物理攻击范围判断是否激活 |
| 1 | 主动出击 | 当前不能攻击时，向最近敌人逼近 |
| 2 | 坚守原地 | 不主动移动，但仍可攻击或使用策略 |
| 3 | 追击指定人物 | 目标参数是人物；目的地随目标当前位置变化 |
| 4 | 前往指定坐标 | 参数为目标 `(x, y)` |
| 5 | 跟随指定人物 | 向指定人物移动，不主动攻击或用策略 |
| 6 | 逃往指定坐标 | 向指定坐标移动，不主动攻击或用策略 |
| 7 | 内部禁用值 | 不进入自动行动调度，不是 EEX 正常的第八种策略 |

本地 EEX 和存档结构对联合参数的使用已经核实：

- 类型 3、5 使用 `u16` 人物参数；
- 类型 4、6 使用两个坐标字节；
- 其他类型不消费这两个参数字节。

原版 58 个 `S_*.eex` 的非空出场项分布如下：

| 阵营 | 类型 0 | 类型 1 | 类型 2 | 类型 3 | 类型 4 | 类型 5 | 类型 6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 友军 | 15 | 62 | 76 | 4 | 1 | 1 | 7 |
| 敌军 | 439 | 799 | 841 | 36 | 78 | 0 | 19 |

运行时 `0x4E`“人物 AI 设定”又出现
`0:175、1:1526、2:17、3:158、4:259、5:9、6:98` 次。这说明类型
不是只在出场时读取，剧情会频繁把坚守部队切成主动、追击人物或前往
坐标。

高可信的原版规则还有：

- 类型 0、1、3、4 在兵力低于约 41% 时，会优先向本阵营第一个出场的
  有名武将靠拢；该人物已撤退时退化为向最近敌人移动；
- 类型 4、6 抵达目标坐标后转为被动；
- 类型 5、6 本身不生成攻击和策略候选。

## 4. 候选动作的三部分

AI 比较的不是单独的“伤害”，而是至少三组候选：

1. **物理攻击价值**：目标是否可击退、伤害占比、目标状态和身份、
   群攻覆盖等；
2. **策略价值**：策略用途类别、目标状态、命中率、回复量、伤害比例
   和覆盖人数等；
3. **站位价值**：恢复地形、战略目的地、能否免受反击、移动成本以及
   格子次序等。

因此，敌军偶尔放弃更高伤害目标并不是随机失误：低兵力单位占用恢复
地形的 `+50`，或者某个格子同时满足战略目的地，可能足以改变最终选择。

## 5. 物理攻击价值

### 5.1 本地内部基础值

本地 `0x00438A20` 的目标价值函数可直接看到以下内部基础值：

| 条件（互斥） | 内部基础值 |
| --- | ---: |
| 预计伤害足以击退目标 | 80 |
| 预计伤害达到目标最大兵力的 10% | 16 |
| 未达 10%，但目标剩余兵力不高于约 40% | 16 |
| 以上均不满足，且行动者为主动型 1 | 10 |
| 以上均不满足，且不是主动型 1 | 2 |

原版实测文章把最终候选中的这组数写成 `78 / 14 / 14 / 8 / 0`。两组
数值恒差 2，说明文章记录的是候选合并后的外部值，而机器码中的函数
保留了统一的内部基线。编辑器或模拟器若要复刻行为，应该比较完整候选
的相对值，不应只把 `78` 当作唯一硬编码入口。

### 5.2 已核实或高可信的加减项

| 条件 | 分值 | 可信度 |
| --- | ---: | --- |
| 目标混乱 | `+8` | 已核实 |
| 目标人物数据 ID `< 174` | 通常 `+4` | 已核实 |
| 友军 AI 攻击首位出场的有名目标 | 再提高到 `+8` 档 | 已核实 |
| 攻击位置不在目标通常反击范围内 | `+1` | 高可信 |
| 使用群体攻击武器但只打到一个目标 | `-4` | 高可信 |
| 群攻连片中的可击退目标 | 每个约 `+10` | 已核实结构、高可信语义 |
| 群攻连片中的“伤害至少 10%”目标 | 每个约 `+4` | 已核实结构、高可信语义 |

预计伤害使用**行动者移动前所在格**的地形修正，而不是候选攻击格的
地形修正。这是原版实测中最容易造成直觉偏差的一点，当前本地伤害估算
调用链与该现象吻合，但仍建议用动态断点做最终验证。

## 6. 站位价值与寻路

### 6.1 恢复地形和战略目的地

本地机器码已核实：

- 低兵力单位的可达格若属于恢复地形，地图候选字节直接 `+50`
  （`0x0043A47F`）；
- 非低兵力单位也会偏好恢复地形，增量随当前地形条件约为
  `+8 / +7 / +6`；
- 站在指定战略目的地上约 `+10`，正交相邻约 `+9`；
- 必须移动后才能施放策略时，该策略候选通常 `-1`。

这解释了“残血敌军宁可打次要目标也要占城池/兵营”的常见现象：恢复格
的奖励比普通的 `10%` 伤害档大得多。

### 6.2 移动和同分规则

原版实测与本地遍历次序共同支持以下优先级：

1. 先选总价值最高的动作；
2. 同价值时，优先移动耗费较低的方案；
3. 仍同分时优先上方格；同一行优先左方格；
4. 路径展开和最后一步的方向顺序为上、右、下、左；
5. 同一攻击格可以攻击多个等价目标时，偏向出场顺序较后的目标。

主动型单位在攻击范围之外时，会先决定理想攻击格，再决定目标和路径。
所以理想格被其他单位堵住时，AI 可能不选择看起来更合理的绕路，甚至
停在原地。这是候选生成顺序造成的确定性结果，不是随机概率。

## 7. 策略使用分类表

本地 `Ekd5.exe` 文件偏移 `0x39580` 保存了 58 个原版策略的 AI 用途
分类；`0x0D` 表示 AI 永不主动使用。该表与 2006 年旧引擎修改资料逐字节
一致：

| 策略编号 | AI 类别 | 用途 |
| --- | ---: | --- |
| `0..8` | `00` | 伤害类 A |
| `9` | `0D` | 禁用 |
| `10..13` | `01` | 伤害类 B |
| `14` | `0D` | 禁用 |
| `15..20` | `02` | 伤害类 C |
| `21` | `0D` | 禁用 |
| `22` | `03` | MP/策略值削减 |
| `23..30` | `0D` | 禁用 |
| `31..32` | `04` | 混乱类 |
| `33..36` | `05` | 伤害类 D |
| `37` | `06` | 禁咒类 |
| `38` | `0D` | 禁用 |
| `39..40` | `07` | 单体兵力恢复 |
| `41..42` | `08` | 群体兵力恢复 |
| `43` | `09` | 单体兵力恢复的另一档 |
| `44..45` | `0A` | MP/策略值恢复 |
| `46..47` | `0B` | 异常状态解除 |
| `48..56` | `0D` | 禁用 |
| `57` | `0C` | 回归/复活类 |

这张表决定“策略应该用什么评分器”，并不直接等于最终分数。最终还要
检查 MP、射程、目标阵营、命中率、伤害或回复量、异常状态以及效果
范围。

原版实测支持的策略取舍包括：

- 混乱、禁咒等异常策略只有在命中率达到内部门槛后才有价值；
- “谎报”类高价值档约为 30；
- 唤醒混乱友军约 `+40`，解除麻痹约 `+30`；
- 远距离恢复通常高于普通大补给；
- 群体恢复与单体恢复能覆盖相同目标时，优先群体恢复；
- 若必须移动后施法，或当前物理攻击范围内已有敌人，策略候选通常
  `-1`；
- 最终价值相同时，大体按“物理攻击、攻击策略、恢复策略、辅助/异常
  策略”的次序处理。

策略函数分支很多，以上具体分值中除用途表和若干常量外仍属于高可信或
待动态验证；不能把新引擎教程中的策略评分直接补进来。

## 8. 对编辑器和模拟器的实现建议

若以后把 AI 预览加入战场编辑器，应把逻辑拆成四层：

1. `ai_goal`：根据 `ai_type` 和联合参数求战略目标；
2. `reachable_tiles`：按移动力、地形耗费和占位生成可达格；
3. `action_candidates`：为每个可达格生成物理、策略、等待候选；
4. `score_and_tiebreak`：分别记录伤害/回复、状态、身份、站位和同分
   决胜项。

每个候选最好输出评分明细，例如：

```text
总分 81
  击中后伤害 >= 10%       +14
  有名人物                 +4
  群攻额外目标             +4
  无通常反击               +1
  低兵力恢复地形          +50
  位置修正                 +8
```

这样才能解释 AI 行为，也便于将动态调试结果逐项回填，而不是只复刻一个
不可检查的总分函数。

## 9. 尚未完全闭环的部分

以下内容仍需用旧引擎动态断点或受控战场样本确认：

- 物理评分内部基线 `80/16/10/2` 到文章最终值
  `78/14/8/0` 的统一归一化发生在哪一层；
- 每一种策略类别的完整公式和命中率门槛；
- 群体策略连片搜索在边界格、同分目标上的精确遍历次序；
- 低兵力转向本阵营首位武将时，对“有名人物”和已撤退目标的全部例外；
- 预计伤害采用移动前地形的调用参数，需用运行时断点做最后确认。

这些是运行机制的剩余验证项，不是文件格式未知项。
