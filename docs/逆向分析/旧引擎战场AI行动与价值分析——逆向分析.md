# 旧引擎战场 AI 行动与价值分析——逆向分析

## 1. 分析对象、证据和阅读约定

本文以仓库中的 `ccz/Ekd5.exe` 为依据，还原战场自动行动的编号转换、调度、战略目标、移动搜索、物理评分、策略评分、候选合并和行动执行。它是一份独立文档，不覆盖《旧引擎战场AI行动与价值分析.md》。

分析日期：2026-09-07。样本 SHA-256：

```text
199b1b67cf966ead46c49b430b9aab84bdc7d4f0e8dfa8e0ebeec5da280b01e0
```

所有结论限定于这个样本。文件时间、发行包年份和论坛中“旧引擎”的称呼不能代替版本标识。本文不把其他版本引擎的说明当作本地程序的实现证据。

证据等级：

| 标记 | 含义 |
| --- | --- |
| A：直接确认 | 指令、跳转、原始表项或本地数据直接支持 |
| B：调用链解释 | 控制流明确，但中文业务名称包含对调用用途的解释 |
| C：边界待验证 | 已定位相关函数，完整行为仍需公共战斗函数还原或动态实验 |

除明确标记 B/C 的业务解释外，本文列出的地址、常量、比较方向和表项均为 A。函数名是本文赋予的解释性名称，不是 EXE 自带符号。

“完整”指覆盖 AI 决策链各层和策略分类表的全部分派入口；不表示已经得到可逐帧替换原程序的战斗模拟器。命中、伤害、装备效果、射程形状和剧情触发依赖公共战斗模块；本文保留其原函数接口，并明确列出尚未展开的部分，不用推测公式填空。

### 1.1 地址口径与复核方式

除标明“文件偏移”的项目外，十六进制地址均为 VA。ImageBase 为 `0x400000`。本样本 `.text` 的 RVA 为 `0x1000`，文件起点为 `0x400`，因此该节内：

```text
file_offset = VA - 0x400000 - 0xC00
```

此公式不能直接用于 `.data` 等其他节。附带脚本按 PE 节表转换地址。

```bash
./venv/bin/python tools/audit_battle_ai_tables.py
/opt/homebrew/bin/llvm-objdump -d --x86-asm-syntax=intel \
  --start-address=0x438a20 --stop-address=0x438d96 ccz/Ekd5.exe
```

复核输出见 [AI 表项与剧本统计](ai_reverse_audit/tables.json)，关键函数反汇编见 [机器码摘录](ai_reverse_audit/disassembly.txt)。

EXE 在代码节内夹有 switch 跳转表。线性反汇编会把表字节误译成指令，并可能让后续函数错位。应从已知函数入口重新反汇编，表项则直接按字节或 `u32le` 读取。

## 2. 最重要的区分：EEX 编号不等于内部 AI 模式

### 2.1 两套编号的映射

`0x459D8B` 是设置单位 AI 的公共入口。它接受外部编号 `0..6`，在 `0x459DFF` 查 `0x48E380`，再调用 `0x442669` 写入活动单位记录。

该表是 7 个小端 DWORD：

```text
外部编号： 0  1  2  3  4  5  6
内部模式： 3  1  2  0  0  4  4
```

| EEX `script_ai` | 脚本层含义 | 内部 `mode` | 目标来源 |
| ---: | --- | ---: | --- |
| 0 | 被动出击 | 3 | 自动探测附近可攻击对象 |
| 1 | 主动出击 | 1 | 自动寻找对立单位 |
| 2 | 坚守原地 | 2 | 当前位置 |
| 3 | 追击指定人物 | 0 | 人物解析成战场槽 |
| 4 | 前往指定坐标 | 0 | 指定坐标 |
| 5 | 跟随指定人物，不主动攻击 | 4 | 人物解析成战场槽 |
| 6 | 逃往指定坐标，不主动攻击 | 4 | 指定坐标 |

内部模式 7 是调度禁用值，不是 EEX 正常的第八类。

**本文从此严格用 `script_ai` 表示 EEX 编号，用 `mode` 表示 `0x425AD0(unit)` 返回的活动单位模式。** 比如机器码 `cmp eax,4` 若比较的是这个 getter，指跟随/逃往，不是 EEX 的“前往指定坐标”。

`0x4148BA`、`0x44CF11`、`0x44D07B` 均调用上述公共设置入口，覆盖运行时命令和战场部署的相关路径。不是只对某一个 EEX 指令生效的特殊转换。

### 2.2 参数与三种记录不能混为一谈

需要区分 EEX 命令参数、存档/部署描述记录、活动战场单位记录。

EEX 在类型字段之后保存人物参数以及两个坐标参数；脚本语法不是只有两个参数字节。部署描述可以把所需内容收拢到两字节联合体，活动单位则将人物目标和坐标目标分开保存。

`0x459E23` 的参数分派：

| `script_ai` | 操作 |
| --- | --- |
| 0、1、2 | 不调用新的目标参数设置分支 |
| 3、5 | 调用 `0x45A751`，把人物 ID 解析成活动战场槽，再写目标槽 |
| 4、6 | 调用 `0x45A6BF`，检查地图坐标范围后写目标坐标 |

`0x44268C` 写目标坐标时，同时把目标槽设为 `0xFF`。`0x45A751` 解析不到人物时返回失败，不会凭空生成有效目标。外层 `0x459D8B` 并未把这些子函数的失败统一向上返回，因此必须保留实际写入顺序：模式可能已经修改，目标更新却没有成功。

切换到不消费目标参数的类型，不等于必然清空全部旧目标字段。复刻时不应自行“清理”原程序保留的状态。

### 2.3 活动战场单位的关键字段

活动单位基址 `0x4B2C50`，跨度 `0x24`。下表不是部署描述的布局。

| 相对偏移 | 类型 | 用途及证据 |
| --- | --- | --- |
| `+00` | u32 | 人物数据 ID，`0x45F670` |
| `+04` | u8 | 活动战场槽编号 |
| `+06/+07` | u8/u8 | 当前坐标，`0x403360` 返回其地址 |
| `+08` | u8 | 指定目标战场槽，`0xFF` 为无目标 |
| `+09/+0A` | u8/u8 | 战略目标坐标，`0x43B490` 复制这两个字节 |
| `+0B` | u8 | 行动顺序，`0x425AB0`、`0x44F980` |
| `+0D` | u8 | 运行标志，`0x425AF0`、`0x442718` |
| `+0E` | u8 | 内部 AI 模式，`0x425AD0`、`0x442669` |
| `+10` | u32 | 当前兵力，`0x472C90` |
| `+14` | u32 | 当前策略值，`0x472840` |
| `+18/+19` | u8/u8 | 能力状态档位，群体评分中的部分分支读取 |
| `+1E` | u8 | 异常状态编码，`0x41E030` |

运行标志 `0x02` 为已行动，`0x04` 为已移动。`0x80` 在剧情强制移动等路径使用，会改变移动预算、禁用普通行动评分和执行；不要将其当作第八种 AI 类型。

人物数据表基址 `0x4A1B68`、跨度 `0x48`，策略数据表基址 `0x4AF4C0`、跨度 `0x46`。编译器复用了相同偏移的小 getter：例如 `0x425AD0` 用于单位时读模式，用于策略对象时读 MP 消耗。**必须同时看 ECX 指向哪种对象。**

## 3. 阵营阶段和行动队列

### 3.1 阵营判定

115 个活动单位槽：

| 槽区间 | 阵营 |
| --- | --- |
| 0..14 | 我军 |
| 15..34 | 友军 |
| 35..114 | 敌军 |

`0x406710` 实际返回 `slot < 35`。因此 AI 攻击/支援的许多判断把我军和友军视为同一侧，而非三方互相独立。

### 3.2 队列生成：`0x44DA7A`

调度前重建本阶段单位的 `action_order`，不是仅在战场初始化时生成一次。函数先清为 `0xFF`，随后分多轮扫描；每轮按槽号升序，只给尚未分配顺序的在场单位写入递增序号。

| 优先轮次 | 条件 |
| ---: | --- |
| 1 | 当前格为恢复地形，调用 `0x4351C0` |
| 2 | 满足 `LowHP`，调用 `0x43A1F4` |
| 3 | `CasterClass` 成立且兵种大类不是 9 |
| 4 | 远程分类 `0x44005D` 成立 |
| 5 | 近战分类 `0x43FF6E` 成立 |
| 6 | 其余在场且仍未分配顺序的单位 |

这里第三轮对大类 9 的排除是兵种判断，不是禁咒状态判断。分类集合会重叠；前面已分配的单位不会再次分配。

兵种原始编号 `raw_class` 与大类 `family` 的转换，由 `0x4077D0` / `0x406906` 完成：

```text
raw_class <= 38 : family = raw_class / 3，整数除法
39..52         : family = raw_class - 26
其他           : 返回字节 27
```

| 分类 | family 集合 |
| --- | --- |
| `CasterClass`，`0x43FFED` | 8、9、10、11、18、19、20 |
| 远程，`0x44005D` | 2、4、5 |
| 近战，`0x43FF6E` | 0、3、4、11、13、17、20 |

### 3.3 调度过滤和重排

`0x44E9B3` 调用队列生成；主扫描为 `0x44E9BF..0x44EBEF`。单位必须满足：

```text
上场状态 == 2
action_order == 当前扫描序号
mode != 7
未设置 0x04 已移动
未设置 0x02 已行动
```

通过后在 `0x44EB1F` 调用单位决策 `0x43AD1C`。

循环并非永远保持同一队列。调度对象 `+0x504` 标志非零时，`0x44EBD9` 再次生成队列、清标志、将扫描序号重置。`0x43B3D5` 在执行回归策略后写 `0x4B420C = 1`，与该重排机制衔接。

## 4. 单位决策总流程

主函数：`0x43AD1C..0x43B40B`。

```text
取得移动预算；强制移动标志 0x80 可改用预算 100
检查指定目标槽；目标不在场则清目标并将 mode 改为 1
检查行动者是否仍在场、未行动、未混乱
以对立单位坐标和行动者射程构建物理候选预筛图、初始评分图
若满足自救分支：选固定槽目标并进行引导/搜索
否则按内部 mode 分派目标与搜索
执行选中的移动
更新到达目标后的模式
若不是强制移动、不是 mode 4：执行物理攻击或策略
更新行动标志
```

注意两点：第一，目标失效处理在后续模式分派之前，因此原本跟随目标的 `mode 4` 也可能转为主动 `mode 1`；第二，行动执行阶段会重新检查或生成目标，不是把评分时的数据永久冻结。

### 4.1 五种正常内部模式

分派表 VA `0x43B40C`：

| mode | 分支地址 | 决策行为 |
| ---: | --- | --- |
| 0 | `0x43AFD4` | 指定人物/坐标引导，同时允许攻击和策略评分 |
| 1 | `0x43B319` | 调用 `0x43A7C9` 主动搜索 |
| 2 | `0x43B327` | 以预算 0 评分，并强制最终位置为当前格 |
| 3 | `0x43B2AE` | 先探测物理攻击对象；存在对象才进行可行动区域评分，否则原地 |
| 4 | `0x43AFD4` | 使用指定目标引导，但跳过物理和策略评分/执行 |

被动模式的激活探测调用 `0x438308` 的 `0x08` 搜索标志，没有改为“枚举可施放的策略”。因此文官能隔远施法，并不必然令被动单位激活。这里的范围包含移动搜索及相关攻击覆盖，不能误写成仅当前一格的武器射程。

### 4.2 主动搜索：`0x43A7C9`

先按本回合移动预算寻找攻击对象；找到后评分行动候选。未找到时，使用更大的搜索预算寻找对立单位，围绕其坐标进行可达性探测、路线构造、引导评分，再评分本回合能到达的格子。仍没有可用对象时回落到原地。

因此“向最近敌人移动”只是一层业务概括。这里的先后由搜索覆盖、移动耗费、地图扫描和占位决定，不等于直接计算人物间曼哈顿距离后取最小值。

### 4.3 指定目标模式

`+08 != FF` 时使用目标单位当前位置；否则使用 `+09/+0A` 坐标。

目标人物自身为内部模式 0 或 4 时，程序还把该人物的目标坐标复制到全局排除坐标 `0x4B2C38`。后续格子评分可以把这个坐标的分数清零，避免单纯追随时抢占被追随者的目的地。

针对找到的指定对象，`0x43B0EB` 可使用强度 20 的目标引导；其他路径常使用强度 10。随后进行目标可达性探测和本回合评分。不能把所有指定目标情况简化成恒定 `+10`。

### 4.4 到达目标和目标失效

`0x440252` 检查到达条件。无人物目标、当前坐标等于目标坐标、mode 为 0 或 4 时，将 mode 设为 3，即内部被动模式。

因此 EEX 的“前往坐标 4 / 逃往坐标 6 到达后变被动”成立，**但实际写入的是内部值 3，不是 0**。有人物目标时转交 `0x4402FC` 检查，不能套用无人物目标分支的坐标相等逻辑。

## 5. 残血、自救与固定槽目标

### 5.1 精确残血谓词：`0x43A1F4`

```text
LowHP(unit):
    if current_hp == 0:
        return false
    if person_id < 174:
        return current_hp <= floor(max_hp * 2 / 5)
    if raw_class == 49:
        return false
    if family == 50:
        return false
    return current_hp <= floor(max_hp / 5)
```

`max_hp` 来自人物数据对象的 `0x40721B`。普通无名单位通常是 20%，有名人物为 40%。这是整数运算，不是统一 `<41%`。

`family == 50` 比较确实在 `0x43A263`。但正常字节输入经上述兵种大类转换，返回字节最大为 27，因而此条件不可达。本文保留机器码事实，不把它擅自改译成“原始兵种 50 也被排除”。

该谓词同时参与行动排序、恢复地形、自救目标、补给策略和诱惑评分。它不是仅供寻路使用的判断。

### 5.2 恢复地形 +50 的前置条件

`0x43A28A` 先清全局自救标志 `0x4B2C24`。`0x43A3B4` 起执行：

```text
if LowHP(actor) and mode not in {2, 4}:
    对地图上地形编号 18..22 的格子：初始评分字节 += 50
    设置自救标志 bit 0
```

对应 EEX 层：坚守类型 2、跟随类型 5、逃往类型 6 不进入这一奖励分支；**EEX 类型 4“前往坐标”映射为 mode 0，仍可以进入。**

加分遍历的是地图格子，之后的搜索/评分才限制哪些格子是本次合法候选。不要把这里误写成已经完成可达性筛选。

### 5.3 自救目标的选择

`0x43AE0C..0x43AFAB` 在自救标志存在、无 `0x80` 强制移动标志、行动者不是槽 35 时执行。

| 行动者一侧 | 目标 |
| --- | --- |
| `slot < 35` | 直接读取槽 0 的当前坐标 |
| `slot >= 35` | 槽 35 在场时读取其坐标，否则置无目标 |

这里没有遍历“第一个有名人物”，也没有目标 `person_id < 174` 条件。两侧的在场检查也不对称：敌军侧显式检查槽 35，我方侧直接读取槽 0。

固定目标有效时使用强度 10 引导、可达性探测和本回合候选评分。无有效目标或相关路线分支失败时，可回落到主动搜索 `0x43A7C9`。

自救分支会改变战略目标，但不是无条件禁止攻击。恢复地形与行动价值仍在后续竞争。

## 6. 搜索图、射程和移动路线

### 6.1 核心搜索函数：`0x438308`

这是多个任务共用的搜索函数，不是一个单纯的“最短路 API”。调用参数含起点、预算、搜索标志、可选目标坐标、占位处理选项。主要标志用途：

| 标志 | 从调用及返回分支可确认的用途 |
| --- | --- |
| `0x02` | 探测指定目标坐标，命中时返回 1 |
| `0x04` | 对访问到的格子调用行动候选评分 |
| `0x08` | 搜索对立单位/攻击覆盖对象 |

使用这些标志时须保留其他参数；不能只依据一个 flag 命名全部调用语义。

搜索图初始化为 `0xFF`，起点为 0。程序按当前累计耗费层扫描地图，外层 y 升序、内层 x 升序，再尝试四个邻格。

`0x4359F5` 使用 VA `0x48DF68` 的方向增量表：

```text
0: ( 0,-1) 上
1: ( 1, 0) 右
2: ( 0, 1) 下
3: (-1, 0) 左
```

地形耗费由 `0x43F7CF(actor, terrain)` 取得，`0xFF` 表示不能按正常路径通过。邻格累计耗费不得超过预算，并受到阵营、占位和强制移动标志影响。

特别需要保留：`0x438725..0x438732` 对已赋值格子直接跳过，不是通用最短路实现中“发现更短距离就更新”的代码。为提高寻路质量而替换算法，可能改变原版候选顺序和行为。

### 6.2 攻击覆盖与目标列表

`0x436586` 根据射程形状和标志展开覆盖。`0x437A04` 处理单格，进行边界、阵营及目标当前兵力检查，并向 `0x4AC748` 目标列表追加槽编号；列表以 `0xFF` 结尾。

`0x437941` 后的收尾可在列表中寻找全局指定目标 `0x4B2C28`；找不到指定目标时保留遍历得到的回退结果。

目标列表来自射程格子的展开顺序，不是统一按单位部署顺序排序。因此“同分一定攻击后出场的人物”不能作为通用规则。

### 6.3 路线构造：`0x437E2E`

路线构造读取之前建立的耗费图，从目标一侧沿更低耗费邻格回溯，考虑占位和剩余预算。邻格方向也是 0..3。

找到的方向序列最后反转，并把每个方向变为 `(dir + 2) % 4`，形成实际前进路线。回溯失败时，可对停下来的位置添加强度 10 或 20 的引导，再交给其他搜索阶段处理。

因而“到目标的距离最短”“最终一步偏好某方向”“候选格最先被评分”是三个不同问题。复刻不能只用一个 `(距离,y,x)` 排序代替整条调用链。

## 7. 物理攻击评分

### 7.1 目标选择层：`0x438965`

先在候选攻击格生成物理射程和目标列表，再依列表顺序调用 `0x438A20`。只有 `new_score > best_score` 才替换目标，等分保留已有目标。

分数以字节保存。初值为 0，所以全为 0 时不产生一个正分优选目标。

### 7.2 单目标基础分：`0x438A20`

下列公式描述合法、存活、对立目标的正常调用。无效槽不能作为独立函数的任意安全输入：原始函数有先取目标对象再作部分校验的访问顺序。

记 `D` 为 `0x43BC4B(actor, target_person_data, 0, 0)` 的伤害估计，`H` 为目标当前 HP，`M` 为目标最大 HP。

```text
if D >= H:                         score = 80
elif floor(D * 10 / M) >= 1:        score = 16
elif floor(H * 100 / M) <= 40:      score = 16
elif actor.mode == 1:              score = 10
else:                              score = 2
```

第二、三项互斥，不能叠加。这里的目标残血百分比与第五节 `LowHP` 是不同算法。

### 7.3 状态和身份加分

`0x438B7B` 检查目标异常位 `0x08`；成立时 `+8`，业务对应混乱。

随后 `0x438BA1..0x438BF5`：

```text
if score > 0 and target.person_id < 174:
    if target.person_id == global_person_496C96 or target.slot == 35:
        score += 8
    else:
        score += 4
```

`global_person_496C96` 由 `0x406630` 读取，可追溯到 `0x412534` 的战斗全局变量人物参数写入。这里不检查“行动者必须为友军”，也不搜索“首位有名人物”。

### 7.4 文官类非击退物理攻击归零

在 `0x438BF8`，状态和身份奖励之后、群攻奖励之前：

```text
if score < 75 and CasterClass(actor):
    return 0
```

正常数据下非击退基础分连同上述奖励达不到 75；击退的基础分 80 可以通过。群攻额外目标的奖励在后面，不能拿它提前突破这道门槛。

这里的 `CasterClass` 包含 family 9。行动排序第三轮排除 family 9，不表示物理评分也排除它。

### 7.5 群体攻击

`0x407818` 取得群攻相关范围配置；有有效非零配置时通过 `0x435AAD` 生成附加目标列表，再调用 `0x438D96`。

物理调用模式参数为 0、策略编号为 `0xFF`：

| 附加列表情况 | 修改 |
| --- | --- |
| 列表为空 | `score = max(0, score - 4)` |
| 附加目标预计被击退 | 每个 `+10` |
| 否则附加目标伤害达到其最大 HP 的 10% | 每个 `+4` |
| 其他附加目标 | `+0` |

必须区分主目标与附加列表。这里不是对整个覆盖范围中的每个人都重新加一遍主目标基础分。

### 7.6 通常反击范围扣分

`0x438CB4` 起用目标的当前位置及通常攻击范围生成覆盖，再检查候选攻击格。`0x438D86` 执行：

```text
if 候选格位于目标通常攻击覆盖内 and score > 1:
    score -= 1
```

准确实现是“范围内有条件扣 1”。不能在所有范围外候选无条件加 1，更不能把它和基础分改成另一套常量后混用。

### 7.7 没有已证实的统一减 2

本地调用链 `0x438A20 → 0x438965 → 0x43A529` 没有统一 `score -= 2`。论坛中另一组基础分不能反向证明本地必有归一化层。

一个只验证物理评分层的例子：普通近战行动者、非群攻、普通有名目标、非混乱、未击退但达到 10% 伤害：

```text
基础 16 + 普通有名人物 4 = 20
攻击格在目标通常攻击覆盖内：19
攻击格不在覆盖内：20
```

这不是最终行动总分，还未合并位置分。

### 7.8 伤害估计与执行伤害的边界

`0x43BC99` 通过 `0x43F84D(actor)` 读取行动者地形修正；`0x43F84D` 再经 `0x403360` 读取活动单位当前坐标。物理评分调用没有把候选攻击坐标传给伤害函数替代当前位置。

所以静态调用链支持“物理 AI 估伤使用移动前格子的地形修正”。是否存在其他路径临时改写坐标，仍可通过动态写断点补充确认。实际战斗中的命中、连击、暴击等不应当作此处评分直接使用的全部随机量。

## 8. 策略候选生成与合法性

### 8.1 可用策略列表

评分搜索 `0x438308` 的 `0x04` 模式在 `0x438434..0x438504` 建立策略列表 `0x4AC7AC`：

```text
按策略 ID 0..67 升序：
    当前原始兵种的学习等级非 0
    学习等级 <= 人物当前等级
    当前 MP >= 策略消耗
    则追加 ID
末尾写 FF
```

候选列表可检查到 67，而主评分 switch 只接受 0..57。58..67 在此评分器中走默认 0 分，不应因为 Data 表有这些策略就认定 AI 会主动使用它们。

单位异常位 `0x04` 会让格子评分跳过策略评分调用，业务对应禁咒。

### 8.2 目标选择：`0x4391DC`

按可用策略列表顺序枚举。策略射程字段为 `0xFF` 时进入按范围直接收集目标并累加的分支；否则生成可选主目标列表，逐一调用 `0x4395AE`。

评分为正且目标槽等于行动者 `+08` 指定目标槽时，可额外 `+10`，见 `0x439397` 和 `0x4394C5`。这是策略外层的指定人物奖励，不属于所有单目标评分分支的基础分。

替换条件是严格更大；同分保留较早候选。按 ID 升序建立的列表，解释了部分较低编号策略的同分优势，但不构成“所有恢复策略都高于所有异常策略”的额外分类排序。

有主目标的分支先把单次评分上限截为 255，再处理指定目标奖励，并写入字节；无主目标分支则先累加多个评分。精确复刻需遵循各处实际截断顺序，不能一律把最终和限制到 255 后假定等价。

### 8.3 公共可用性谓词

`0x4390EF(actor_slot, target_slot, strategy_id)` 先调用 `0x41FEC9`、`0x420422`，再按策略目标阵营字段判断双方同侧或异侧。

本文把这两个前置函数的合并结果记为 `ValidStrategyTarget`。它们属于公共策略模块，包含施放/目标资格相关条件。下文“通过合法性检查”均包含它们，不表示只检查阵营、MP 或命中率。

`0x4395AE` 的四个参数从调用点可识别为目标槽、策略 ID、候选坐标、候选地形。当前主评分分支大量使用活动单位对象中的当前位置/状态；不能仅因为形参里有候选坐标，就断言所有下层估算采用候选格。

## 9. 策略分类表与全部主评分分支

### 9.1 原始分派表

类别字节表 VA `0x43A180`、文件偏移 `0x39580`，长度 58。`0x4397BF` 查类别，`0x4397C5` 跳转；跳转地址表 VA `0x43A148`。

| 策略 ID | 名称/组 | 类别 | 实际入口 |
| --- | --- | --- | --- |
| 0..8 | 灼热至水龙 | 00 | `4397CC` |
| 9 | 海啸 | 0D | `43A13B` |
| 10..13 | 旋风至风龙 | 01 | `4397CC` |
| 14 | 砂暴 | 0D | `43A13B` |
| 15..20 | 落石至诱惑 | 02 | `4397CC` |
| 21 | 晕眩 | 0D | `43A13B` |
| 22 | 谍报 | 03 | `439D27` |
| 23..30 | 钝兵至挑拨 | 0D | `43A13B` |
| 31..32 | 谎报、谎言 | 04 | `4399E5` |
| 33..36 | 毒烟、毒雾、定身、定军 | 05 | `4397CC` |
| 37 | 封咒 | 06 | `439DAF` |
| 38 | 八阵图 | 0D | `43A13B` |
| 39..40 | 小补给、大补给 | 07 | `439AAE` |
| 41..42 | 援队、援军 | 08 | `439B4A` |
| 43 | 输送 | 09 | `439AAE` |
| 44..45 | 建言、献策 | 0A | `439E84` |

00、01、02、05 共用同一入口；07、09 也共用入口。类别编号不同不代表一定使用独立公式。

下文定义：`Q = u8(floor(target_hp * 100 / target_max_hp))`，`C = CasterClass(target)`。表中数值均为内部主评分，不含外围指定人物、格子和其他合并项。

### 9.2 伤害公共分支：00 / 01 / 02 / 05

通过合法性检查后调用 `0x43BFAA` 得到预计策略伤害 `D`：

```text
if D >= target_hp:
    score = 76
else:
    if floor(D * 10 / target_max_hp) >= 3: score = 30
    elif floor(D * 10 / target_max_hp) >= 1: score = 10
    else: score = 1
    再应用下列按策略 ID 的附加项
```

只有非击退分支执行以下特殊项：

| 策略 | 修改及指令位置 |
| --- | --- |
| 20 诱惑 | 行动者未满 HP 时 `+5`；行动者 `LowHP` 时再 `+10`，`439954..4399A2` |
| 33、34 毒烟/毒雾 | `Q >= 40` 时 `+8`，`4398EE..439904` |
| 35、36 定身/定军 | `0x45AFCA(actor_person,target_person,1)` 返回 0 时 `+10`，`43990F..43994C` |
| 其他 | 无此层特殊加分 |

定身分支的 `0x45AFCA` 是一个额外公共判断，本文保留其准确调用与返回方向；其全部业务语义列为 C，不用“必然能限制移动”等描述替换。

有群体效果配置时，随后调用第十节的群体模式 0，但传入有效策略 ID。因此策略附加目标通常按资格 `+3`，不是照搬物理群攻的 `+10/+4`。

### 9.3 混乱策略：04

入口 `0x4399E5`。合法性检查通过后，调用 `0x43B73F` 的结果至少为 35 才有正分。该函数在调用链中用作命中率估计，语义标记 B。

```text
命中率估计 < 35：0
否则：15
若 Q >= 80：再加 15
```

80 的比较对象是目标兵力百分比，不是命中率。群体配置非零时交给群体模式 0 合并。

### 9.4 封咒：06

入口 `0x439DAF`。通过合法性检查且目标 family 属于 `{8,9,10,11,18,19,20}` 后：

```text
命中率估计 < 60：0
否则：15
若 Q >= 80：再加 7
```

这里的类别判断与 `CasterClass` 集合相同。不能把混乱的门槛 35 套给封咒。

### 9.5 单体兵力恢复：07 / 09

入口 `0x439AAE`。通过合法性检查后：

| 条件 | 内部评分 |
| --- | ---: |
| 目标不满足 `LowHP` | 0 |
| 39 小补给且目标 `LowHP` | 50 |
| 40 大补给且目标 `LowHP` | 55 |
| 43 输送且目标 `LowHP` | 60 |

此处没有按实际回复点数线性计分。普通无名目标的 20% 门槛同样适用。

### 9.6 群体兵力恢复：08

入口 `0x439B4A`。主目标合法且 `LowHP` 为 50，否则主分为 0；有群体范围时调用群体模式 1。

附加合法目标 `floor(hp * 100 / max_hp) < 60` 时每个 `+5`。这个 60% 条件与主目标的 `LowHP` 不同；不要复用同一个残血谓词。没有附加目标时还可能触发群体空列表的减 4。

### 9.7 谍报：03

入口 `0x439D27`。通过合法性检查后：

```text
actor_mp <= floor(actor_max_mp / 5)
且 target_mp >= 30
则 score = 20；否则 0
```

因此它不是只要能削减对手 MP 就使用的通用攻击策略。

### 9.8 建言/献策：0A

入口 `0x439E84`。合法目标还须同时满足：

```text
target_mp <= floor(target_max_mp / 5)
actor_mp >= strategy_mp_cost + 6
```

按目标依次判断：

| 目标条件 | 分值 |
| --- | ---: |
| family == 9 | 1 |
| 否则 CasterClass 成立，或 `0x407A09(target_data,0x3C)` 成立 | 12 |
| 否则 family == 0 | 6 |
| 其他 | 0 |

`0x407A09` 是装备相关效果查询；`0x3C` 在这里是查询参数，不能未经继续追踪就直接称为“道具 ID 60”。

### 9.9 觉醒/大觉醒：0B

入口 `0x439BE3`。合法性检查通过后基础分为 5，按目标异常状态字节做互斥分派：

| 状态编码 | 条件与附加值 | 常见业务解释 |
| --- | --- | --- |
| 2 | 目标 mode 不是 3、2 时 `+25` | 麻痹，B |
| 4 | 目标 CasterClass 时 `+30` | 禁咒，B |
| 8 | `+35` | 混乱，B |
| 其他 | 不追加 | 保留基础 5，仍受合法性过滤 |

所以常见最终主分分别为 30、35、40，而不是把 30/35/40 作为无条件追加项。这里比较的是状态编码的相等值，不是对所有状态位独立累加。

内部 mode 3 是 EEX 被动，mode 2 是坚守。不能误译成“追击指定人物时不解除麻痹”。有群体配置时调用模式 5，每个附加合法且异常状态非零的目标 `+3`。

### 9.10 回归：0C

入口 `0x439FBE`。本地 `Imsg.e5` 对 57 的说明为“使行动完毕的一个我军部队可以再次行动”。它不是撤退单位复活。

通过公共目标合法性检查后，依次：

```text
target.mode 为 3 或 2：0
target.family == 9：0
target.family == 0：15
target.family == 19：15
target.family == 5：10 + rand_mod(4)
target.family == 8：10
其他：rand_mod(5)
```

`rand_mod(4)` 为 0..3，`rand_mod(5)` 为 0..4。条件有顺序，不叠加。

### 9.11 默认类别 0D 和越界策略 ID

主分初始化为 0。类别 0D 和 ID 大于 57 都直接走返回分支 `0x43A13B`，没有正分主动使用依据。

这是 AI 主动评分限制，不是说玩家、剧情或公共战斗模块不能执行该策略。

## 10. 群体评分辅助函数：`0x438D96`

接口按调用点整理为：

```text
GroupScore(extra_slots, base_score, scoring_mode, actor_slot, strategy_id)
```

附加列表以 `FF` 终止。空列表先将基础分减 4，最低为 0；非空列表逐项处理，最后返回基础分与附加分之和，非正总和归零。

| mode | 每个附加目标的贡献 |
| ---: | --- |
| 0，strategy_id == FF | 物理预计击退 `+10`，否则伤害达到最大 HP 的 10% `+4` |
| 0，有效 strategy_id | 通过策略目标合法性 `+3`；若还等于行动者指定目标槽再 `+3` |
| 1 | 合法且整数 HP 百分比 `<60` 时 `+5` |
| 2 | 合法且 `0x41DF90(target)<4` 时 `+3` |
| 3 | 合法且 `0x41DFB0(target)<4` 时 `+3` |
| 4 | 合法且 `0x41DFB0(target)<4` 时 `+3` |
| 5 | 合法且 `0x41E030(target)!=0` 时 `+3` |

模式 2..4 的读取条件是按本地机器码保留的，尤其模式 3、4 读取相同 getter，不擅自“修正”为不同能力。当前上述原版 AI 主评分表主要调用 0、1、5。

群体目标几何由 `0x435AAD` / `0x435B3E` 生成。主目标、附加目标、无主目标范围累加，是三种不同层次；不能把以上奖励重复加到同一个对象上。

## 11. 格子价值、合并和最终选择

### 11.1 普通地形分：`0x43A4BF`

```text
if candidate_terrain in 18..22:
    return 8
else:
    return max(0, current_terrain_factor(actor) - 10)
```

第二项通过 `0x43F84D` 读取行动者当前地形适应值。它不是逐候选读取该格子的地形适应值。

相对普通格子的恢复地形优势在某些条件下表现为 8/7/6；真实代码应保留上述计算。低兵力的 +50 与这里的 +8 可以叠加，两者不是必然互斥。

### 11.2 战略目标引导：`0x438178`

调用参数为目标坐标、强度和行动者槽。强度小于 9 时直接返回。

对当前格子的引导只在相应评分字节为 0，且占位等检查通过时写入。之后按四邻递归：

```text
strength > 10：下一层 strength - 10
否则：下一层 strength - 1
```

通常强度 10 对应中心 10、四邻 9；强度 20 对应中心 20、一层 10、再一层 9。递归入口小于 9 立即停止。

原始兵种 15、16 在 `0x438262..0x438286` 不继续向邻格扩展。已有 +50 等非零分值的格子也不会被此函数当作空白引导格直接叠加强度。不能用一个无条件 `goal_bonus(distance)` 公式替代全部逻辑。

### 11.3 单格合并：`0x43A529`

先检查候选占位：已有其他单位占据且不是行动者当前格时，直接结束。

设 `V` 是格子的现有评分字节，包含先前恢复地形/战略引导结果；`P`、`S` 初始为 0。

无强制移动标志时：

```text
if mode != 4:
    若物理候选预筛图中该格非 FF，或候选就是当前位置：
        P = best_physical(candidate)
    若行动者未禁咒：
        S = best_strategy(candidate)
    V = u8(V + max(P, S))

V += min(terrain_score(candidate), 255 - V)

if candidate == actor.current_position and P == 0:
    V += min(1, 255 - V)
```

物理预筛图由 `0x43A28A` 建立：在 `0x43A297` 先取得**行动者**的射程形状，再对每个在场对立单位，以该对立单位的坐标为中心、使用先前保存的行动者射程调用 `0x436586`。它不是各敌人自身武器射程的威胁图。`0x43A5FF` 检查该格是否非 FF，当前格则另行放行。相关非对称射程边界仍应按原图复现。

之后，候选若等于排除坐标 `0x4B2C38`，`V` 被清零。

### 11.4 原地 +1，而不是策略函数统一 -1

`0x43A6CE..0x43A729` 的实际实现是：**候选为当前位置且物理评分 P 为 0 时，格子分最多加 1。**

某些情况下，这让“移动后施法”相对原地施法差 1。但此奖励同样可能作用于原地等待候选，不是所有策略主评分函数直接减 1；若当前位置有正分物理候选，也不会得到该奖励。

### 11.5 同分处理的准确层次

| 层次 | 更新条件 |
| --- | --- |
| 同格物理目标 | `new > best`，否则保留原目标，`0x438A03` |
| 同格策略候选 | `new > best`，否则保留原策略，`0x4393BD` / `0x4394E6` |
| 同格物理和策略 | 策略严格大于物理才记录为策略；相等时选物理，`0x43A77D` |
| 不同候选格 | 格子总分严格超过全局最好值才替换，`0x43A767` |

地图搜索有耗费层、y/x 扫描和四邻展开顺序；单格评分发生在邻格被发现时。故只看到 y/x 升序不能推导出所有等分结果都等于全局 `(耗费,y,x)` 排序。

最忠实的实现是保留枚举顺序与严格比较条件。若采用现代寻路或统一排序，需要明确那是行为调整，而非已经证明等价的原版复刻。

### 11.6 字节分数和溢出顺序

单格评分缓冲与多个最佳分字段是 u8。`V + max(P,S)` 直接以字节相加，随后普通地形分和原地奖励才按剩余空间限制到 255。策略层还有先限制、后加指定目标奖励、再写字节的路径。

因此不能把所有中间值提升为无限精度整数，最后一次性 clamp，声称与原引擎逐位一致。原版正常场景是否触及具体溢出边界，应使用受控样本检验。

## 12. 移动和行动执行

### 12.1 移动：`0x43A956`

选定坐标无效、行动者不在场或目标就是当前位置时，不执行移动。

否则调用 `0x437E2E` 构造路线，逐步用方向更新朝向和当前坐标。正常移动完成后设置 `0x04`，再更新地图占位/显示状态。强制移动标志 `0x80` 走不同的记录和显示路径。

这一步发生在实际攻击/施法之前，故物理评分时的地形与行动结算时的地形可能不同。

### 12.2 物理行动：`0x43AAFB`

在实际当前位置重新生成通常攻击范围，优先匹配已记录目标；还要检查强制移动、mode 4、武器可用性、目标存在和已行动标志等条件，之后调用公共攻击执行模块。

目标被击退且 `0x407A09(actor_data,0x2E)` 装备效果查询成立时，存在再次生成范围、再攻击一个目标的分支。这个执行后续不是前述单目标基础分的额外常量。

结束时设置已行动、已移动标志。不能把“评分选中目标”直接等同于“所有状态下都会执行成功”。

### 12.3 策略行动与回归重排

若全局选定策略 `0x4B2C44 != FF`，主函数通过 `0x441488` 准备行动，再调用 `0x43DC99` 执行策略。

策略 ID 为 57 时设置调度重排标志，允许回归导致的再次行动与新的队列安排衔接。没有选中策略时走物理执行分支；该分支也可能因没有合法目标而不攻击。

## 13. 随机数和可重复性

`0x47FAE7` 更新全局随机状态 `0x48ECD4`：

```text
state = u32(state * 0x41C64E6D + 0x3039)
r = (state & 0x7FFF0000) >> 16
```

`0x47FB13(n)`：当 n 小于 2 时返回 0，否则返回 `r % n`。

回归评分会调用它，所以不同候选的枚举次序可能改变随机数消耗及后续结果。测试需要固定随机种子和完整调用次序，不能只对最终选中的候选抽一次随机数。

其他命中、伤害、剧情也可能消耗同一随机状态。只固定 AI 局部随机种子而忽略公共模块，不能保证原版整回合逐步一致。
