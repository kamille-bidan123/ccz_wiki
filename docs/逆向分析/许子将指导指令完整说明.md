# 许子将指导：指令与流程机制

游戏文字中的人物名为“许子将”，人物ID为157。

本页说明原版指导指令的入口、教学分支、演示和奖励机制；[文字版剧本](许子将指导文字剧本.md)列出对白、选项及顺序注解。尚未确定的原版调用语义另行注明。

## 指令身份与调用关系

|项目|现有证据结论|
|---|---|
|EEX操作码|`0x10`，小端命令字节为`10 00`|
|参数|无；教学文字、演示和奖励不作为该命令参数保存在EEX里|
|本地语料|117份R/S脚本中仅`S_00.eex`出现一次|
|原分派入口|`0041590D → 00433359`|
|解析名称|`battle_operation_tutorial`|
|执行方式|S命令分派进入程序内部的教学流程，返回后继续后续S命令|
|角色|曹操0、刘备32、许子将157；人物ID与战场槽号不能混用|

因此，S脚本中看到的一条“许子将指导”会进入可执行程序内部的整段流程。仅解析出一个opcode，不会自动得到其中的教学和奖励。其前后的人物显示/消失由外围S命令控制，不应全部算进0x10内部。

现有规格记载指令位于S00指导人物显示相关操作与人物消失之间；具体时点应按S00所在的嵌套条件执行，不自行改成每回合或每次进入战场都执行。

## 整体分支

```text
进入0x10
  → 见面对白；曹操朝向许子将
  → 根据通关记录，使用初次上阵/已有经验的开场对白
  → 是否听取指导？
      选项1：接受
        → 基本操作
        → 是否继续？否则转到教学致谢
        → 友军与敌军
        → 是否继续？否则转到教学致谢
        → 我军操作与移动/取消
        → 是否继续？否则转到教学致谢
        → 地形与最后提示
        → 教学致谢
      选项2：拒绝
        → 拒绝对白；跳过四段教学和教学致谢
  → 根据通关记录，进入或跳过升级/金钱奖励
  → 根据宝物图鉴条件，进入或跳过宝物/金钱奖励
  → 告辞
  → 返回S解释器，继续后续命令
```

关键区别：拒绝听教学、途中不再继续、拒绝升级、拒绝宝物是不同选择。**拒绝教学不会直接跳过后面的两类奖励条件。** 全程听完后出现的“选择上面的选项”是原教学对白，不是本页新增的游戏规则。

入口规格和九个子函数支持以下分段说明；现有证据尚缺调度函数`433359`的完整原文，顶层调用及资格判定链仍需补全。

## 九个现有原版函数

|函数|职责|分支/效果|
|---|---|---|
|`433404`|开场与同意指导|通关记录改变对白；原选项返回0表示接受|
|`4333D2`|继续询问|“非常想听 / 不太想听”|
|`43353C`|第一段：基本操作|白色选择框、鼠标操作、人物情报与预估信息|
|`4337F4`|第二段：友军与敌军|刘备、阵营标识、移动与攻击范围、解除显示|
|`433BC8`|第三段：我军部队操作|蓝色移动范围、移动、取消、下个行动窗口|
|`43419F`|第四段：地形|地形情报、四类策略图标、地形适应及最终提示|
|`433512`|接受教学后的致谢|中途退出或听完者汇合；最初拒绝者不进入|
|`4347FF`|通关记录奖励|升级或金钱，最后有共同对白|
|`434D33`|宝物图鉴奖励|接受宝物或拒绝后获金钱|

各函数Evidence ID、原字符串地址、GBK字节和完整伪代码随[提取数据](许子将指导证据/battle_tutorial.json)、[原分析记录](许子将指导证据/opening_native.json)一起保存。函数内字符串数组按首次引用排列，**不能单独当作多分支的播放顺序**。

## 教学演示与参数语义

第一段把白框引向曹操，并展示人物概况；第二段转向刘备并展示友军/敌军、范围和阵营颜色；第三段演示我军选择、移动和取消、行动选择；第四段展示地形信息、火水地风图示与地形适应。详细对白及穿插调用见[文字版剧本](许子将指导文字剧本.md)。

|原调用|应如何理解|
|---|---|
|`45965D`|按人物ID说话；原文“附带说明的”等用词原样保留|
|`42DE12`|返回值从0起算；画面选项编号从1起算，例如返回0对应第一项|
|`457428`|朝向调用，含目标人物/方向/反向及前后等待|
|`45778F`|动作调用；原参数0/1/2/5等是动作，不是方向|
|`433726 / 43378D`|选择框显示/隐藏|
|`438308`|搜索和候选/移动范围构建，不应当成单纯绘图|
|`459487`|脚本人物移动，不能因教程使用就解释成瞬移|
|`4350C0`|普通操作移动/返回路径，与脚本移动是不同入口|
|`47467A`|请求指定音效；例如演示中的SE0、SE1，奖励中的SE39、SE10、SE14|
|`403340 / 42C4E0`|原时钟等待及消息处理；1tick=50ms不等于只相乘即可推出整段墙钟时长|

动作与朝向是不同调用。部分内部调用的UI对象与具体效果仍待核实，文字剧本保留相应地址。

## 通关记录奖励

奖励函数按`DAT_004B2C10`的值分支。其上游统计口径须结合Svcmn读取核实，不能仅凭奖励分支断定它统计所有通关还是不同结局。

|记录值|玩家选择|原结果|
|---:|---|---|
|0|不出现此奖励选择|跳过此段|
|1|接受 / 不需要|曹操+1级 / +2000金|
|2|接受 / 不需要|曹操+2级 / +4000金|
|大于2|希望提升6级 / 希望提升3级 / 不需要|曹操+6级 / +3级 / +10000金|

接受升级的调用顺序是：许子将动作5、SE39、10tick等待、恢复动作0、调用`4073B8`增加曹操等级、读取新最大HP/MP并写回战场曹操的当前HP/MP、曹操恢复动作0。该奖励增加等级，不改变兵种。

拒绝升级后播放SE10、通过`40DBED`增加对应金钱，再调用`42F699(2)`提示。奖励段最后的“我非常期待曹大人今后……”对白不依赖玩家是否接受升级。等级上限、经验及成长细节继续由原升级函数决定，本页不新增公式。

## 宝物图鉴奖励

宝物图鉴条件满足时进入此段。子函数`434D33`从开头就播放图鉴集齐对白，上游资格判定不在该函数内部，完整资格调用链仍待补全。

|选择|原结果|
|---|---|
|1.非常乐于接受|动作5、SE39、20tick等待、恢复动作0；筛选并发放宝物；SE14及提示|
|2.不要那些宝物|SE10、增加30000金及提示|

发放循环遍历物品ID`0..103`，只对`409600(item)`非零者调用`40D79C`；第三参数由`40C6EA(item)`是否等于2决定，末参数0。**不是无条件增加104件物品。** 现有材料尚不足以在此页完整展开这两个getter及仓库溢出/重复拥有的所有结果，保留原调用与筛选式供后续核对。
